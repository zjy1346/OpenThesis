# OpenThesis 2.0.1 版本更新规划：模型目录恢复与 OT 工作室可用性修复

> 状态：已实施，已完成自动化与部分人工联合验收；用户已于 2026-08-25 明确授权上传  
> 规划日期：2026-08-24  
> 当前基线：OpenThesis 2.0.0 本地候选包  
> 目标版本：OpenThesis 2.0.1  
> 触发原因：用户对 2.0.0 候选包进行人工测试后发现模型配置与 OT 创作工作室存在阻断性缺口

> 联合验收要求：2.0.1 实施完成后，必须同时逐项核对 docs/releases/2.0.0.md 与本文，不能以 2.0.1 的新增测试替代 2.0.0 的既有验收。

## 一、版本定位

2.0.1 不是增加新宣传功能，而是修正 2.0.0 验收未能覆盖的真实使用问题：

1. GLM 卡片使用了不匹配的图标；
2. 新连接没有自动提供内置模型目录，用户仍被迫手动填写模型 ID；
3. 旧版已经存在的在线模型刷新体验没有完整迁移到新的 Rust 模型中心；
4. 新连接只显示“未测试”，用户找不到可直接执行的连接测试；
5. `.ot` 创作工作室的两个操作按钮没有形成可靠的统一基线；
6. 参数问号提示框在实际环境中出现透明背景和低可读性问题。

2.0.1 完成并通过本文验收前，2.0.0 本地候选包不视为可交付版本。2.0.1 将生成新的本地测试包；在用户测试并明确授权前，不提交、不推送、不发布 GitHub Release。

## 二、人工测试证据与根因

### 2.1 GLM 图标身份错误

人工截图中 GLM 卡片显示为带有 `KG` 字样的圆形标识，无法让用户识别为智谱 GLM。

当前实现：

- `desktop/src/assets/providers/glm.png` 来自 THUDM GitHub 组织头像；
- `desktop/src/assets/providers/SOURCES.md` 将其记录为 `GLM / THUDM`；
- THUDM 头像同时表达 Knowledge Engineering Group（知识工程组）等组织身份，并不是模型中心所需的智谱开放平台/GLM 服务商图标。

结论：这不是图片缩放问题，而是资源选择错误。

### 2.2 2.0 模型中心丢失旧版内置模型目录

旧版 `src/openthesis/model_catalog.py` 已经具备：

- 每个 Provider 的 `recommended_models`（内置推荐模型）；
- `models_path`（在线模型目录路径）；
- `merge_model_ids()`（内置列表与在线列表稳定去重合并）；
- 在线刷新失败时保留内置列表；
- 当前手动填写值不在目录时仍保留该值。

2.0 Rust `ProviderDefinition` 目前只有 Provider 级字段，没有 `recommended_models` 或等价模型预设字段。前端 `ModelCenterView.tsx` 只有在用户点击“发现模型”成功后才填充候选模型；发现不可用时只能使用“手动模型 ID”。

同时，当前 Rust 注册表把 DeepSeek、Qwen、Kimi、Kimi Global、GLM 和 Gemini 的 `supports_discovery` 设为 `false`，导致这些卡片连在线刷新入口都不显示。2.0 因此只迁移了“连接”概念，没有迁移旧版成熟的“内置列表 + 在线刷新 + 手动兜底”完整体验。

### 2.3 测试功能入口断层

Rust 后端已有真实的 `test_model()`：

- 发起最小文本请求；
- 声明视觉能力时追加最小图片请求；
- 成功后更新连接和模型健康状态；
- 失败后保存安全错误状态。

但 React 前端只在“已配置模型”列表中显示测试按钮。新连接尚未添加模型时，页面只显示连接状态“未测试”，没有连接级测试操作，也没有内置候选模型可供添加，于是用户无法到达已有测试能力。

结论：后端能力并非完全缺失，缺失的是新连接到候选模型、连接测试和模型测试之间的产品流程；同时需要补充一个不依赖已配置模型的连接级测试命令。

### 2.4 `.ot` 操作按钮未真正归一

`检查草稿` 使用 `.secondary-button`，`检查并导出` 使用 `.primary-button`。全局 `.primary-button` 带有 `margin-top: 24px`，而 `.studio-actions` 没有重置该外边距。即使两个按钮都设置为固定宽度和最小高度，深色按钮仍会被额外向下推移。

此外两个按钮没有统一声明 `display`、内容对齐和图标间距，导致文字按钮与带图标按钮的视觉基线不稳定。

### 2.5 参数提示框背景声明失效

OT 工作室新样式大量使用以下变量：

- `--ink`；
- `--muted`；
- `--canvas`；
- `--success`；
- `--danger`。

这些变量当前没有在根主题中定义。提示框背景使用：

```css
background: color-mix(in srgb, var(--ink) 94%, #20352a);
```

因为 `--ink` 未定义，整条 `background` 声明无效；提示框仍使用白色文字，从而形成截图中的“透明/浅色背景上的白字”。提示框又渲染在可滚动的 `.report-stage` 内部，没有使用 Portal（传送门）脱离滚动容器，进一步增加裁切、层叠和定位异常风险。

## 三、2.0.1 实施方案

### 3.1 恢复“内置模型 + 在线刷新 + 手动兜底”

Rust Provider Registry（服务商注册表）继续作为 2.x 的唯一运行时权威目录，但补齐模型级元数据。不得重新让 Python 或前端维护第二套权威列表。

`ProviderDefinition` 至少增加：

- `recommended_models`：随应用离线发布的模型预设；
- `models_path`：可选的在线模型目录路径；
- `default_test_model_id`：连接级测试所用的明确模型；
- 模型别名、默认能力和费用类别所需的最小元数据；
- 目录版本或来源说明，便于后续更新和审计。

迁移规则：

1. 复用旧版 `model_catalog.py` 的功能设计和合并算法；
2. 旧列表只作为迁移输入，实施时仍须依据各 Provider 当前官方文档核对模型 ID，不能盲目复制已经失效的名称；
3. 点击一个已有连接后，候选模型立即显示，不要求先刷新，也不要求手动输入；
4. 内置模型始终排在前面；在线发现结果稳定去重后追加；
5. 在线刷新失败、超时、未授权或 Provider 不提供目录时，内置模型仍保持可选；
6. 手动模型 ID 移到“高级/自定义模型”折叠区，作为兼容新模型或私有 Endpoint 的兜底，不再作为主要路径；
7. 在线刷新只读取当前连接保存于 Windows 凭据管理器中的密钥，密钥明文不得返回 React 或 Python；
8. 在线目录只提供模型 ID，不得远程修改 Endpoint 白名单、安全策略、计费策略或 Provider 定义；
9. Ollama 只发现用户电脑已经安装的模型，不安装 Ollama，不下载模型权重。

目标交互：

```text
添加 DeepSeek 连接
        ↓
立即看到经过版本核对的 DeepSeek 内置模型
        ↓
可直接选择并添加
        ├─ 可选：刷新在线模型目录
        └─ 高级：手动填写尚未收录的模型 ID
```

### 3.2 补齐连接级测试

在每张已保存连接卡片中增加明确的 `测试连接` 操作，不再让“未测试”成为没有出口的状态。

后端新增连接级测试路径：

- 对有内置模型的 Provider，使用注册表中明确展示的 `default_test_model_id` 发起最小请求；
- 测试 UI 必须告诉用户本次测试使用哪个模型；
- 对 Ollama 或支持模型目录的连接，可以先验证目录，再用选定/默认模型执行最小生成请求；
- 对没有内置模型的自定义连接，要求用户先选择在线发现模型或填写模型 ID；
- 测试不会静默创建研究任务，不会切换模型，不会修改用户已有模型；
- 成功标记连接为 `可用`；失败显示 `未授权`、`不可用`、`限流`或安全的配置错误；
- 错误信息不得包含 API Key、完整响应正文或可能含秘密的 URL；
- 连接级测试与已配置模型的能力测试并存。配置模型后，仍可逐模型验证文本和视觉能力。

前端状态必须完整覆盖：默认、悬停、键盘焦点、测试中、成功、失败、禁用和重试。

### 3.3 GLM 图标替换

删除当前 `KG`/THUDM 组织头像作为 GLM Provider 图标的映射。

新资源要求：

- 使用能够明确表达智谱/GLM 的图标，而不是研究组织头像；
- 优先采用具有明确开源许可、支持本地打包的静态资源，例如 LobeHub `Zhipu` 或 `ChatGLM` 图标；
- 资源必须固定版本并复制到应用本地，运行时不得从 CDN 获取；
- 在 `desktop/src/assets/providers/SOURCES.md` 记录资源名称、固定版本、原始地址和许可证；
- 保留文字 `GLM`，不能仅依赖颜色或图形传达身份；
- 在浅色背景、200% 缩放和 34/32/46 像素容器中保持清晰、不裁切、不变形。

Lobe Icons 项目提供 `ChatGLM` 和 `Zhipu` 图标并采用 MIT 许可证；实施时选择与当前智谱开放平台连接最匹配的变体，而不是继续使用 THUDM 头像。

### 3.4 OT 操作区归一

按钮外边距由容器控制，按钮组件本身不负责页面间距：

- 移除或局部覆盖 `.studio-actions` 中 `.primary-button` 继承的 `margin-top: 24px`；
- 两个按钮统一 `margin: 0`、高度、宽度、圆角、内容布局和文字基线；
- 两者都使用 `inline-flex`，并统一 `align-items: center`、`justify-content: center`；
- `检查并导出` 的下载图标保留，但图标不得改变文字基线；
- 中文、繁体中文和英文均保持单行；
- 操作区靠右排列，间距一致；在空间不足时以整体响应式布局处理，不允许其中一个按钮单独换行或错位；
- 忙碌和禁用状态不能改变按钮尺寸。

不应只添加一个针对截图尺寸的像素补丁；需要修复全局按钮外边距与局部组件职责混淆。

### 3.5 参数提示框可读性与层级修复

首先补齐 OT 工作室使用的主题变量，并为关键颜色提供不依赖 `color-mix()` 的确定性回退值。

提示框本身采用：

- 实色深色回退背景；
- 不低于 4.5:1 的文字对比度；
- 至少 13px 的正文尺寸和舒适行高；
- 合理的最大宽度、内边距和自动换行；
- 明确边框、阴影和指向触发器的视觉关系；
- 通过 React Portal 渲染到 `document.body`，避免被 `.report-stage` 的滚动和层叠上下文裁切；
- 根据视口边缘自动选择上方或下方，并限制在当前窗口内；
- 首个鼠标悬停允许短延迟，相邻提示可即时显示；
- 键盘聚焦、触控点击和 Escape 关闭均可用；
- `prefers-reduced-motion` 下仅保留必要淡入，不执行位移动画。

提示文本保留现有含义，但可按可读性分成短句，不允许为了适应小框而缩小到难以阅读。

## 六、真实界面验收

必须使用全新隔离数据目录完成一次完整流程：

1. 打开模型中心并确认 GLM 图标正确；
2. 新建一个测试连接；
3. 不点击在线刷新，确认内置模型已经出现；
4. 执行一次连接测试，观察 `未测试 → 测试中 → 可用`；
5. 模拟认证失败或断网，确认错误可读且可重试；
6. 刷新在线模型，确认新模型与内置模型合并而不是覆盖；
7. 添加至少一个模型并执行模型级测试；
8. 关闭并重开应用，确认连接、模型与健康状态保留，密钥不回显；
9. 打开 `.ot` 创作工作室，分别悬停和键盘聚焦三个问号；
10. 在标准窗口、1366px、窄窗口与 200% 缩放下检查提示框和操作按钮；
11. 完成一次草稿检查和一次 `检查并导出`；
12. 对导出的 `.ot` 执行编译、内容哈希和往返一致性校验；
13. 使用已测试模型发起一次实际研究，确认 2.0.1 没有破坏研究选模和运行流程。

所有页面、按钮、弹框、下拉栏、输入框、状态提示和系统保存框继续按 Emil 设计规范检查；不能只验证本次截图区域。

## 七、安全与兼容约束

- 不内置模型权重，不内置或安装 Ollama。
- 不把 API Key 移回 React、Python、SQLite、`.ot`、日志、研究快照或普通配置文件。
- 在线刷新不得执行远端代码或远程替换安全策略。
- 测试请求必须由用户点击触发，并明确显示测试模型；不得自动消耗可能收费的模型额度。
- 不自动从免费模型切换到收费模型。
- 现有 2.0 模型连接和已配置模型数据库结构应尽量原位迁移；如需 schema 变更，必须有升级测试和失败回滚保护。
- 不恢复第三方 `.othesis` 兼容入口。
