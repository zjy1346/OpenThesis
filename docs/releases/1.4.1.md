# OpenThesis 1.4.1 修改需求与验收清单

状态：**已实施并通过发布前验收**
建立日期：2026-08-12
规则：本文档是 1.4.1 的冻结需求清单。用户确认后才允许修改代码；验收时必须逐项核对，不得用“基本完成”代替任一条验收结果。

## 1. 本次问题与已确认根因

### 1.1 研究进度长时间停留在“下载官方财报（6/6）· 16%”

- 后端在下载最后一份财报前写入“6/6、16%”，随后同步进入 PDF 解析、表格识别、质量校验和财务档案构建。
- 上述耗时阶段没有持续发布独立的进度事件，前端只能反复显示最后一次下载快照，因此用户会误以为程序卡死在下载。
- 前端虽然约每 350ms 轮询一次，但只是展示后端最后一次 `message/percent`，无法自行判断真实工作阶段。

解决方向：建立稳定的阶段 ID、阶段详情和单调递增进度；在下载完成后立即切换到“解析/校验”阶段，并在逐文件、逐表或逐 Agent 的安全边界发布可观察进度。长耗时外部调用必须继续支持取消和明确的超时/失败状态。

### 1.2 阶段性报告与“重新生成综合报告”提示重叠

- 报告页会同时渲染“正在重新生成综合报告”和“阶段性报告”两个状态元素。
- 两者共用 sticky 定位和负 margin，形成截图中的重叠。

解决方向：改为一个统一的报告状态区。同一时刻只显示一个最高优先级状态；重试中显示“正在重新生成综合报告”，完成或失败后再恢复阶段性报告说明。取消 sticky 负 margin 叠放方案。

### 1.3 比亚迪 2026 Q1 同期收入增长为空

- 当前财报选择策略在某年度已有年报时，会丢弃该年度的季度报告。
- 因此 2026 Q1 被保留，但用于同比的 2025 Q1 被丢弃；计算器找不到同周期基准，只能显示“—”。
- 这不是显示层格式问题，而是同比所需的上年同期数据在进入财务计算前已经被选择策略删除。

解决方向：当最新期间是 Q1/H1/Q3 时，额外保留上一年度相同期间作为同比伴随报告；仍然禁止把季度累计值与完整财年混算。若官方披露确实缺失，则显示明确的“缺少上年同期披露”，不能伪造增长率。

### 1.4 增长机会显示为空

- 最终综合报告只要含有 `growth_opportunities` 字段，渲染器就认为该章节已经完成，即使字段为空或无效。
- 这会阻止已经保存的独立“增长机会”研究产物作为回退内容显示。
- 当前比亚迪最近一次真实运行中，增长机会 Agent 还出现了模型返回空内容：`structured_output_valid=false`、`empty_content`、`opportunities=[]`。因此本问题同时包含“空最终字段遮蔽回退”和“上游模型空响应”两层。

解决方向：只有通过结构校验且至少包含一项可展示机会时，才把最终综合报告视为已提供增长机会；否则优先使用有效的独立增长机会产物。若两者都无有效内容，显示清晰的阶段失败说明和可重试入口，不把“模型空响应”伪装成“证据不足”。

### 1.5 README 仍展示过期的 v1.2.0 亮点

- 中英文 README 仍将 `v1.2.0` 标记为当前 Windows 测试版，并保留整段旧版本亮点。
- 这些内容与当前正式版本不一致，会误导从 GitHub 首页了解项目的用户。
- 本版本删除中英文 README 中的旧提示和整段 `v1.2.0` 亮点；历史发布说明与依赖锁文件中的正常版本号保留。

## 2. 实时研究进度系统

### 2.1 数据与交互规则

- 后端发布稳定的 `stage_id`，前端只根据稳定 ID 本地化，不再依赖后端自由文本作为主标题。
- 进度百分比必须单调不回退；一个阶段内部使用 `current/total` 或已完成的子步骤更新。
- 下载完成后必须立即进入解析阶段，不能继续保留“正在下载”。
- 正计时从研究任务真正开始时计为 `00:00`，每秒更新，采用后端 `elapsed_seconds` 校准，避免轮询抖动导致计时跳回。
- 计时格式：不足一小时为 `MM:SS`，一小时及以上为 `HH:MM:SS`；使用等宽数字，禁止宽度抖动。
- 研究完成并成功加载报告后，整个研究进度区域卸载，不再展示计时、阶段文字或等待句子。
- 取消中、云端识图授权中、失败和部分完成均有独立状态，不伪装成普通运行状态。
- 进度事件不得包含 API Key、个人路径、原始模型响应或财报敏感临时内容。

## 3. 等待期间的双语轮播文案

### 3.1 播放规则

1. 研究开始后的第 0–10 秒固定显示首句。
2. 第 10–20 秒固定显示第二句。
3. 20 秒后，将随机句子装入“洗牌袋”，每句展示 5 秒；一轮内不重复，重新洗牌时也不得连续重复上一轮末句。
4. 文案切换只使用 140–180ms 的透明度淡入淡出，不做位移、缩放、弹跳或高度动画。
5. 开启 `prefers-reduced-motion` 时取消淡入淡出，直接替换文字。
6. 页面进入后台再返回时，根据实际已用时选择当前句子，不高速补播错过的句子。
7. 研究结束、失败或取消时立即停止定时器；报告生成并显示后不再展示这些句子。

## 4. 前端呈现与动效约束

依照 `emil-design-eng` 的界面与动效规则，本次不以花哨动画掩盖长等待，而是提高状态的真实性、层级和可读性。

| Before | After | Why |
|---|---|---|
| 单行“下载（6/6）·16%”，后续解析时文字不变 | 主阶段、解释句、子步骤、百分比和正计时共同展示 | 用户能确认程序正在继续工作，而不是靠装饰性动画猜测 |
| 后端自由文本直接成为界面主标题 | 稳定 `stage_id` + 前端中英文目录；动态计数作为独立参数 | 避免中英混用，后续新增阶段更可维护 |
| 多个 sticky 状态胶囊叠在报告顶部 | 单一状态槽，根据优先级替换内容 | 消除重叠和视觉噪音 |
| 文案切换可能造成区域高度变化 | 文案区预留稳定高度，只做短透明度切换 | 防止布局跳动、闪烁和阅读焦点漂移 |
| 进度条使用频繁布局变化 | 保持 `transform: scaleX()`，单调更新，短 ease-out；减少动态时直接更新 | 维持流畅度并尊重辅助功能设置 |

进度区域最低要求：

- 主标题突出当前阶段，说明句为次级文字。
- 右侧同时显示百分比与已用时间，例如 `42% · 03:18`。
- 详细子步骤显示真实对象，如“正在解析第 3/6 份财报”或“财务 Agent 2/3 已完成”。
- 等待轮播句与当前阶段说明视觉上分区，不能被误认为技术状态。
- 980×680、125%/150% Windows 缩放和英文长文案下不截断、不覆盖取消按钮。
- 不引入循环加载动画来假装工作；所有进度变化必须来自真实阶段或明确的“仍在处理”计时。

## 5. 数据与报告修复方案

### 5.1 同期收入增长

- 修改披露选择策略：保留最新季度/中期报告，并为其保留上一年度相同期间的官方报告。
- 比较键必须是相同期间：Q1↔Q1、H1↔H1、Q3↔Q3；禁止 Q1↔FY。
- 解析和质量门分别验证两个期间；上年同期被拒绝时，不计算同比，并向报告提供可读的缺失原因。
- 比亚迪回归基准：2026 Q1 报告存在时，选择集中应包含 2025 Q1；报告不再无原因显示“同期收入增长：—”。

### 5.2 增长机会

- 将“是否已渲染”从“字段是否存在”改为“是否存在通过结构校验的非空机会列表”。
- 最终综合报告的有效机会优先；其为空/无效时，回退到独立 `growth-opportunities` 产物。
- 独立产物也为空时，区分：模型空响应、JSON 格式无效、证据验证失败、确实没有足够证据。
- 对可重试的模型空响应提供针对该阶段的重试能力；不得重跑已完成的财报下载、识别和其他 Agent。
- Markdown 与 HTML 两套报告必须采用相同的回退规则。
