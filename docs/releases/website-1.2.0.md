# OpenThesis Website 1.2.0 重构需求与验收清单

状态：**已实施并完成本地验收，等待用户检查**  
建立日期：2026-08-17  
取代：`website-1.1.0.md` 的已实施页面方案  
说明：`1.2.0` 仅是内部网站变更记录编号，不得出现在公开网页文案或界面中。用户明确批准本方案后才允许修改 `website/` 代码。

## 1. 用户反馈

本轮不是对现有动画的小修，而是重新定义网站的动态表达。

- 当前页面没有达到“流畅、华丽、像连续镜头一样的滚动动画”要求；主要动画只是章节舞台约几十像素的上下位移和透明度变化。
- 研究进度截图被固定宽高比和 `object-fit: cover` 二次裁切，导致截图内容不完整。
- 市场章节的超大中文标题换行失控，行间距过紧；装饰性证券标签也可能侵入正文区域，形成视觉重叠。
- 最终 CTA 出现 `OpenThesis 1.4.1`，首屏和能力说明也绑定到 1.4.1。官网应采用长期有效的产品文案，不应要求每次应用升级时同步修改页面版本号。

## 2. 已确认的原因

### 2.1 动画只有一个模板

当前 `website/src/App.tsx` 中的 `useChapterChoreography()` 对六个章节执行完全相同的逻辑：

- 章节舞台仅在约 `-14px` 到 `14px` 之间纵向移动。
- 透明度仅随距离中心点轻微变化。
- 首屏只有背景噪声视差和正文淡出。
- 市场、证据、Agent、进度、恢复和本地历史没有各自独立的时间线，也没有跨章节共享的视觉元素。

因此页面虽然“有动画”，但没有视觉事件、镜头推进、内容演示或场景转换。

### 2.2 产品截图按错误比例强制裁切

当前 `website/src/styles.css` 对普通截图强制 `aspect-ratio: 1.49`，对进度截图强制 `aspect-ratio: 1.42`，同时使用 `object-fit: cover`。

实际中文进度截图为 `660×250`，宽高比约 `2.64`。放入 `1.42` 的容器后，接近一半的水平内容会被裁掉，用户看到的标题开头、按钮或 Agent 状态不完整。

### 2.3 中文展示标题没有受控换行

市场章节的正文列最大宽度约 `530px`，标题最大字号可达 `88px`，但没有为中文设置安全行宽、平衡换行或逐行容器。`line-height: .96` 又使上下两行字形过于接近。装饰标签没有独立的裁切边界，进一步增加与正文相撞的风险。

### 2.4 网站文案与应用版本耦合

`website/src/App.tsx` 在首屏眉题、能力说明、最终下载按钮和截图回退框中多次写死 `1.4.1`。这使官网变成版本发布页，而不是长期维护的产品宣传页。

## 3. 新的动态设计目标

目标不是添加更多零散入场动画，而是把首页改造成一条由滚动控制的、可反向播放的连续研究镜头：

> 官方披露进入工作台 → 市场身份被统一 → 证据被放大和校验 → Agent 展开研究 → 进度真实推进 → 失败路径重新接回报告 → 研究沉淀为本地历史。

参考站值得借鉴的是“固定摄像机 + 滚动驱动时间线 + 场景资产在同一画面中重组”的方法，不复制其产品、3D 模型、图片、视频、字体、品牌或源代码。

## 4. 动画技术方案

### 4.1 动画引擎

- 引入 GSAP 与 ScrollTrigger，使用一个桌面主时间线管理 pin、scrub、章节标签、快速反向滚动和清理。
- 保留浏览器原生滚动，不引入 ScrollSmoother，不劫持滚轮，不强制 snap。
- pinned 容器本身不参与 transform；只动画其内部视觉层，避免 ScrollTrigger 尺寸计算错位。
- 预定义场景动作使用 GSAP/CSS transform、opacity、clip-path 和 SVG stroke；不在滚动过程中修改布局属性。
- 所有时间线在 React effect 清理时完整 `kill()`，语言切换只更新文字，不重新创建错误的滚动起点。
- GSAP 与 ScrollTrigger 适用于普通网站实现；使用前将其标准许可和版本加入 `THIRD_PARTY_NOTICES.md`。

### 4.2 桌面滚动结构

- 新增一个约 `650–850svh` 的主故事容器，内部画布固定在视口中。
- 文案按时间线进入和退出，产品舞台保持连续，不再每个章节重新出现一张互不关联的卡片。
- 每个场景设置明确的稳定起点、展示段和稳定终点；快速滚动或反向滚动时直接跟随当前滚动进度，不重播入场。
- 每个场景采用独立动画语法，不复用“统一上下移动”模板。

### 4.3 移动端与辅助功能

- `980px` 以下不 pin 长时间线，改成分段静态叙事和短距离遮罩揭示，保证内容、截图和 CTA 完整。
- `prefers-reduced-motion: reduce` 关闭 pin、3D 位移、持续缩放和路径运动，只保留约 `200ms` 的透明度/颜色反馈。
- 触摸设备不启用鼠标追踪、倾斜或 hover 位移。

## 5. 七段连续镜头分镜

### 5.1 首屏：从披露文件进入工作台

- 完整官方披露页面作为低对比背景从 `scale(1.08)` 缓慢归位。
- 一条珊瑚色证据线沿真实表格区域绘制，标题按行通过 clip-path 揭示。
- 滚动继续时，披露页通过圆角遮罩收束成 OpenThesis 报告窗口，形成第一个共享元素转场。
- 不再只让噪声文字上下移动。

### 5.2 市场：同一证券身份在空间中汇合

- 三条 SVG 披露路径分别从 SEC、A 股官方披露和 HKEX 进入中心工作台。
- 路径按 `stroke-dashoffset` 绘制，真实证券代码沿路径移动；中心工作台从轻微透视角度归正。
- 文案逐行切入，装饰图层被限制在舞台容器内，绝不侵入正文列。
- 场景结束时三条路径合并成下一章节的证据线。

### 5.3 证据：完整界面 + 局部放大镜

- 主舞台始终先展示一张完整、未裁切的真实产品截图。
- 第二个同源图层只作为局部放大镜，通过 clip-path 圆形窗口放大页码、来源、期间和币种；它不能替代完整截图。
- 证据标签以 40–60ms 的短 stagger 出现，质量门通过后共同收束到确定性计算轨道。

### 5.4 Agent：观点展开，计算保持独立

- 七个研究角色从同一证据核心沿不同方向展开，连接线按顺序绘制。
- 确定性计算轨道保持在中心，不随 Agent 卡片漂移。
- 滚动后半段 Agent 观点重新汇聚为报告页面，建立下一镜头的视觉连续性。

### 5.5 研究进度：完整产品界面真实推进

- 重新制作进度截图资产：保留完整应用框架和完整进度卡，不出现被裁掉的文字、按钮或 Agent 状态。
- 不展示“运行合成演示”等与真实公司截图要求冲突的区域。
- 网页的说明性动画位于截图外层：进度轨道绘制、阶段注释高亮和真实 Agent 状态依次聚焦；不得修改截图内的真实数值或伪造完成状态。
- 时间线指示器与产品截图保持同一节奏，而不是在截图下方另画一套互不对应的假进度。

### 5.6 恢复：失败路径重新连接

- 报告画面分成“已完成内容”和“失败阶段”两条路径。
- 失败路径短暂降低饱和度并显示明确原因，定向重试线随后重新连接到综合报告。
- 已完成内容始终保持稳定，不整体消失或重播。

### 5.7 本地历史与最终 CTA

- 报告窗口缩小并沿 Z 轴进入本地历史栈，形成多个追加式论点版本。
- 模型入口与会话级密钥边界从侧面进入，最终归位为一个干净、静止的下载画面。
- 最终按钮使用长期有效的“下载 Windows 便携版 / Download for Windows”，不显示应用版本号。

## 6. 截图重制规则

- 所有产品截图继续来自真实上市公司研究，不使用 Synthetic Demo 或虚构财务数据。
- 重新捕获至少 `1440×900` 的中文和英文产品界面；需要局部特写时，从同一完整原图生成独立衍生资源。
- 完整截图使用原始宽高比或 `object-fit: contain`；禁止对主截图使用会切掉产品内容的 `object-fit: cover`。
- 只有明确标记为装饰性放大层的副本允许裁切，且同一场景必须同时存在完整主截图。
- 进度场景不得包含合成演示入口、空报告占位或与真实研究状态冲突的界面。
- 截图进入网页前逐张检查：四边完整、文字未切、无浏览器扩展悬浮按钮、无 API Key、Token、邮箱、机器路径或内部凭证。

## 7. 中文排版修复

- 桌面展示标题改成逐行容器，每一语义行独立控制，避免浏览器在任意汉字位置自动断行。
- 桌面标题行使用 `white-space: nowrap`，通过更合理的列宽和 `clamp()` 字号保证完整；移动端提供单独的受控换行。
- 中文展示标题行高调整到约 `1.0`，不再使用造成字形碰撞的统一 `.96`。
- 使用 `text-wrap: balance`、`line-break: strict` 和语言相关最大行宽；英文与中文拥有不同的展示字号上限。
- 市场舞台设置独立 `overflow: clip` 和安全内边距，证券标签不得越过舞台边界。
- 在 `1790×846`、`1440×900`、`1280×800`、`980×680`、`390×844` 分别进行截图比对。

## 8. 永久化官网文案

公开页面移除所有应用版本号，包括但不限于：

- 首屏 `OPEN SOURCE · LOCAL FIRST · 1.4.1`。
- 中英文首屏对应眉题。
- “1.4.1 还提供这些能力”等能力说明。
- “Get OpenThesis 1.4.1 / 获取 OpenThesis 1.4.1”。
- 截图加载失败时的 `OpenThesis · 1.4.1`。
- 容易被误解为应用版本号的本地历史 `14.1 / 14.0` 标签，改用研究日期或论点版本语义。

保留：

- 下载链接继续指向 GitHub `releases/latest`，自动获得当前最新发布。
- 页面内容宣传产品长期能力；以后只有能力、截图或品牌发生实质变化时才更新官网。
- 版本号可以存在于内部变更记录、Git 历史和发布系统中，但不进入官网可见文案。
