# OpenThesis Website 1.4.1 主站 .ot 生态全屏入口方案

状态：**用户已批准本地实现、提交与推送；等待 GitHub Pages 线上验收**  
建立日期：2026-08-23  
目标站点：`https://openthesis.cc.cd/`

## 1. 用户要求

- 主页面需要新增一张与现有产品故事章节同等规模的整屏页面，用于浓缩介绍 `.ot` 生态。
- 用户在主页面理解核心价值后，可以进一步点击进入已经设计完成的独立 `.ot` 生态页面。
- 新场景必须保持现有官网的黑色、珊瑚色、全屏滚动叙事与高级动效语言。
- 本文将用户消息中的“.op”按既有项目上下文理解为“.ot”；如果用户实际指向另一种格式，需要在实施前重新确认。
- OpenThesis 与 `.ot` 均按正式交付能力表述，不使用计划状态或未来承诺。
- 主站仍不展示产品版本号，避免每次版本更新时同步修改官网。
- 用户已明确授权创建提交、推送并触发 GitHub Pages 部署。

## 2. 当前实现与问题定位

### 2.1 当前入口过轻

- `website/src/App.tsx` 的桌面导航和移动菜单已经存在 `.ot 生态 / .ot Ecosystem` 链接。
- 主页面的内容叙事仍只有六个全屏故事场景；模型中心场景结束后立即进入“完整能力盘点”。
- 因此用户必须先主动点击导航，才能理解 `.ot` 是什么；主页面没有承担生态认知与价值传达。

### 2.2 现有时间线固定为六场景

- `website/src/motion/storyTimeline.ts` 明确要求 `scenes.length === 6`，并在索引 `0–5` 间完成场景交接。
- 桌面 `.story-film` 高度为 `700svh`，ScrollTrigger 结束距离为 `600%`。
- `website/src/motion/mobileStoryTimeline.ts` 会遍历全部场景，但细节动画映射只有六项。
- 新增整屏入口必须同步扩展桌面时长、场景交接和移动端细节映射，否则会出现静态场景、提前结束或不可见状态。

## 3. 信息架构决策

### 3.1 插入位置

新增场景放在：

`模型中心 → .ot 生态浓缩场景 → 完整能力盘点 → 最终下载 CTA`

原因：

- 模型中心先解释本机配置和凭据边界，随后自然过渡到“研究对象可以流转，但秘密不随行”。
- `.ot` 场景作为六段产品故事的总结，将证据、计算、工作流、报告与安全边界收束为一个研究对象。
- 用户可继续浏览完整能力盘点，也可直接进入 `/ot/` 深入了解，不形成强制跳转。

### 3.2 场景职责

主站浓缩场景只回答三个问题：

1. **它是什么**：类型化、版本化、可验证的研究对象。
2. **它带走什么**：工作流、证据、计算、论点与报告。
3. **它不带走什么**：API Key、任意代码与默认网络访问。

独立 `/ot/` 页面继续承担对象结构、生命周期、六类包、OT Studio 与安全供应链等完整说明。主站不复制独立页全部内容。

## 4. 推荐文案方向

### 4.1 中文

- Kicker：`07 / .ot 生态`
- 主标题：`让研究流转，证据始终随行。`
- 正文：`.ot 把工作流、证据、计算与报告组织成一个类型化、版本化、可验证的研究对象；它可以跨工具流转，但不会携带凭据或任意代码。`
- 辅助句：`一个对象，保留研究的结构与证明。`
- CTA：`探索 .ot 生态`

### 4.2 English

- Kicker：`07 / THE .ot ECOSYSTEM`
- Headline：`Research can travel. Proof stays with it.`
- Body：`.ot carries workflows, evidence, calculations and reports in one typed, versioned and verifiable research object—without credentials or arbitrary code.`
- Supporting line：`One object keeps the structure and the proof.`
- CTA：`Explore the .ot ecosystem`

最终实施时可在不改变事实边界的前提下微调断行、字数与标点，以避免中英文窄屏重叠。

## 5. 视觉方案

### 5.1 整屏构图

- 延续参考截图的左右双栏整屏结构：一侧是主文案，另一侧是代码原生 `.ot` 研究对象。
- 作为第七个故事场景，桌面端默认使用“对象在左、文案在右”的交错关系，与前一场模型中心形成空间换位。
- 视觉中心不是应用窗口或截图，而是一枚可点击的 `.ot` 对象：
  - 中心对象：`research.ot`
  - 四个真实核心信号：`SCHEMA`、`EVIDENCE`、`HASH`、`PERMISSIONS`
  - 内部内容带：`workflow`、`facts`、`calculations`、`claims`、`report`
  - 状态：`VERIFIED`
- 连接线只表示真实的数据归集与验证关系，不使用无意义红线、随机轨迹或持续漂浮装饰。
- 不使用真实应用截图，也不制作虚构产品界面或演示公司。

### 5.2 点击与反馈

- `.ot` 对象视觉整体为明确链接，点击进入 `/ot/`。
- 文案区同时提供有文字标签的 CTA，确保用户不必猜测图形能否点击。
- 不让整张整屏章节都成为链接，避免用户滚动、选择文字或触摸空白处时误跳转。
- 桌面精细指针环境下：
  - 对象悬停仅提升边框、珊瑚色状态与不超过 `1.01` 的轻微深度。
  - 连接线向 CTA 方向完成短距离聚焦，提示跳转结果。
- 按下时对象与 CTA 立即缩放反馈；按钮使用约 `0.97`，大对象使用约 `0.99`，不等待释放才响应。
- 键盘焦点必须清晰，Enter 可进入独立页面；视觉对象提供准确的 `aria-label`。

## 6. 动效方案

本轮实施继续遵守 Apple Design 与 Emil Design Engineering：

- 每段动画必须解释“多个研究内容被归集为一个可验证对象”，不为华丽而随机旋转。
- 所有滚动动画由用户滚动位置控制，可前进、反向和中断。
- 主要逐帧属性限于 `transform`、`opacity` 与 SVG `stroke-dashoffset`。
- 不逐帧动画宽高、布局、阴影、模糊或 `top/left`。
- 不从 `scale(0)` 出现，不使用弹跳；研究产品保持克制、稳定的物理感。

### 6.1 桌面端场景交接

- 将故事场景数量从六扩展为七。
- 桌面 story film 从 `700svh` 扩展为约 `800svh`，ScrollTrigger 结束距离从 `600%` 对应扩展为 `700%`。
- 在时间点 `6` 从模型中心交接到 `.ot` 场景。
- 动画顺序：
  1. 上一场模型中心淡出。
  2. 主标题与说明沿同一方向短距离出现。
  3. 内容层按 `workflow → evidence → calculations → report` 汇入中心对象。
  4. Schema、Hash、Permissions 等状态依次确认。
  5. CTA 与对象的可点击状态最后显现。
- 场景离开与返回使用同一路径和 scrub 状态，不设置阻塞式自动播放。

### 6.2 移动端

- 保持普通文档流，不复制桌面 pinned 时间线。
- 新场景由现有移动端控制器统一遍历，新增第七项细节动画。
- 对象结构垂直排布，先文案、后对象、再 CTA；不依赖左右并排。
- 内容层使用约 `12–22px` 位移、`0.98–1` 缩放和短 stagger。
- 减少连接线数量，只保留表达归集与验证的必要路径。
- `390 × 844` 与 `430 × 932` 下必须无横向溢出、标题重叠、标签裁切或点击区域遮挡。

### 6.3 无障碍与性能

- `prefers-reduced-motion: reduce` 下取消路径绘制、位移与视差，直接呈现清晰终态；保留短促透明度反馈。
- 触摸设备不使用 hover 状态。
- CTA 与对象链接使用明确 focus-visible 样式。
- 颜色不能成为唯一的已验证状态表达；同时使用图标与文字。
- 对象链接的触摸目标不得小于 44px，点击跳转不被动画延迟。
