## 1. 产品目标

用户提交研究后可以继续阅读报告、配置模型和准备下一项研究；随时知道哪些任务正在运行、排队或需要处理，并能直接找到对应操作。任务管理不应占据所有页面，也不应把完整工作台压缩进浮层。

保留暖白底色、深绿强调色、细边框、圆角、克制阴影、现有侧边导航及报告正文排版。此次改变信息层级和交互组织，不改品牌，不改研究方法、提示词、缓存策略或后端调度顺序。

## 3. D1：入口与用户路径

### 任务中心是唯一完整管理页

- 侧栏“研究任务”直接进入整页；标题右侧“发起研究”。徽标保留未结束数量，需要处理时增加文字/图标区分，不能只靠颜色。
- 全局页头增加紧凑“任务：运行 N · 排队 N”入口；存在待处理项则优先显示“需处理 N”。无任务时仍能打开任务中心，不展示空进度卡。
- 点击页头入口打开宽约360–420px的快捷面板：显示运行、待处理和排队摘要、公司、阶段、排队位置及“全部任务”。只做查看和跳转，不嵌入财报列表、调用历史、恢复授权或诊断表单。
- 点击摘要直接进入任务中心并选中该任务；完成通知可直接打开其报告。关闭快捷面板不取消、不清空选中任务、不改变当前报告。
- 提交成功后留在原页，用短暂通知提供“查看任务”；不自动弹开任务详情，不自动切换到空报告。提交中的按钮防重复点击；接受失败保留表单内容。
- 任务完成不抢焦点、不替换正在阅读的报告。需处理状态保留在全局入口及任务中心，关闭通知不能消除待处理事实。
- 从报告进入任务中心再返回，恢复原报告及滚动位置；发起研究草稿在普通导航切换后仍保留，明确“清空”才重置。

## 4. D2：任务中心布局

```text
研究任务                                        发起研究
进行中（运行/排队） | 需处理 | 已结束 | 全部
┌ 任务列表 280–320px ┬ 所选任务：公司 / 状态 / 当前阶段 ┐
│ 公司、状态         │ 唯一的下一步提示及主操作         │
│ 阶段或排队位置     │ 概览 | 资料准备 | 模型研究 | 诊断 │
│ 模型、用时         │ 当前页签内容                    │
│ ……                 │                                 │
└───────────────────┴─────────────────────────────────┘
```

- 列表默认“进行中”；用户选定的筛选、任务和页签不被轮询重置。已选任务状态变化后保留详情并告知已移出筛选，不突然跳到另一家公司。
- 运行列表采用稳定顺序；排队位置以服务端为准，视觉排序不得修改执行顺序。已结束包含完成、失败、取消，并明确区分。
- 状态筛选复用已有 `research.jobs.list.states`。扩展 `useResearchTasks` 的查询状态，筛选变化重置分页和增量游标；丢弃旧查询的迟到响应。不能只筛选已加载的50条却展示为全库结果。
- 本版不引入跨历史全文搜索、拖拽重排或批量恢复，以免扩大调度范围。
- 内容容器不足约900px时，列表和详情二选一；进入详情显示“返回任务列表”，恢复列表滚动和选择。按实际容器宽度切换，不仅按屏幕宽度。
- 宽屏列表和详情各有一个滚动区域；详情中禁止再套固定高度进度滚动窗。头部、页签和操作区域占用明确布局空间，不遮盖内容。
- 删除任务页 `calc(100dvh - 固定值)` 高度依赖；壳层用 flex/grid、`min-height: 0` 分配剩余空间，提示条出现或窗口缩放后仍能到达底部操作。

## 5. D3：任务详情与动作归属

详情首屏只回答：研究谁、当前在做什么、等了多久、是否要我处理。保留总用时和最近实际活动；不虚构百分比、预计时间或“模型正在思考”。排队显示前方任务数，远端没有活动证据时显示等待响应。

| 页签 | 默认内容 | 详细信息 |
|---|---|---|
| 概览 | 阶段摘要、资料/研究完成情况、当前下一步 | 失败原因展开、已保存成果入口 |
| 资料准备 | 财报名称、年份、识别状态、具体缺口 | 展开单份文件的页面/窗口明细 |
| 模型研究 | Agent、模型、真实活动状态、用时 | 单条展开调用尝试、输入/输出/缓存用量；未知保持未知 |
| 诊断 | 导出诊断、技术原因和事件 | 原始错误码、请求标识等，不混入研究正文 |

- 首次打开运行任务默认概览；需要处理时首屏显示对应动作，不能要求先滚到底部或去诊断页寻找。用户切换页签后不随进度自动切回。
- 模型切换恢复、视觉上传授权、预算追加放在所选任务详情的“需要处理”区域，使用当前 `job_id`、`revision` 和计划标识。去掉列表底部泛化 `children` 插槽，改成具名的任务动作区域。
- 每种状态一个优先主动作：排队可取消；运行可查看进度/取消；需处理提供对应恢复或授权；结束提供查看报告。归档等低频动作放次级菜单。
- 任务执行结束不等于报告完整；阶段性报告明确“查看已有研究”，不得用成功颜色掩盖缺口。是否可打开成果以真实 run/报告可用状态为准。
- 重复原因只显示一次；诊断码折叠。同一任务的恢复动作如果在报告页也存在，复用动作逻辑和能力判断，不维护两套互相矛盾的状态。
- 换任务立即清除上一任务的授权输入，详情加载前不显示可点击的旧动作；动作进行中防重复提交，冲突刷新详情并保留说明。关闭面板不终止后台命令。
- 保留远端结果未知、可能重复计费、云端上传等已有必要授权，不将它们隐藏在“更多”中，也不因美化自动授权。

## 6. D4：视觉与交互规范

- 复用 `styles.css :root` 的 `--canvas`、`--surface`、`--accent`、`--line`、`--ink` 等变量；保留 `#f4f5f2` 底色、`#27684b` 强调和现有图标体系，不新增 UI 框架。
- 正文/交互标签以14–16px为主，辅助文字12–13px，任务标题16–18px；不通过把字缩成9–10px解决拥挤。间距以8/12/16/24px组织，圆角沿用12–16px。
- 列表行用轻边框/选中底色区分，详情以分隔线组织，减少每层都包卡片；首屏不放等待格言和大面积空白装饰。
- 任务页只显示一次页面标题；整页不再出现浮层式关闭叉号。快捷面板有关闭按钮、Escape关闭、焦点回到触发器，不能锁住整页操作。
- 进度变化只更新对应行；不自动滚动、不抢焦点。通知轻量浮于边角且不覆盖主要按钮，可关闭；重要待处理事项仍可长期找回。
- 所有图标按钮有可读名称，状态同时有文字；支持键盘访问和现有三种语言。页签、表单 ID 使用实例唯一值，避免并存组件同名。
- 不改报告正文的字体、行距和阅读宽度；仅移除重复的任务级提示，并保留研究质量及证据警告。

## 8. 可观察验收标准

1. 发起A研究后阅读旧报告，再发起B；A保持原任务、B正常排队，正文不被巨大进度卡替换；所有任务入口指向正确任务。
2. 任意页面一次点击可看任务摘要；侧栏一次点击进入完整任务中心；关闭快捷面板后原报告位置不变。
3. 运行、排队、取消中、需授权、需换模型、远端未知、失败、阶段性完成、完整完成、空列表均有明确状态和下一步，不混用“完成”。
4. 任务切换、轮询和分页期间不展示错误公司的详情或操作；待处理表单永远绑定当前任务；筛选结果覆盖服务端对应集合。
5. 1280×720、1440×900、1920×1080以及系统150%缩放下，主要按钮、材料列表和模型调用都能访问；窄窗口自动单栏，无整体横向滚动、文字竖排或底部遮挡。
6. 详情一次只滚动一层；展开调用历史可看到底部；通知出现不挤压阅读区，后台变化不抢焦点/滚动位置。
7. 关闭/重开界面、归档、恢复、取消及退出应用保留原业务语义。UI导航不新增模型调用，不改变请求材料、缓存前缀和队列调度。
8. 开发补充对应交互回归，并在实际候选桌面包记录上述状态的可见操作与截图；原有测试通过不能替代视觉验收。该验收清单交开发执行，本轮决策不运行测试或真实研究。

## 11. 已完成的改动

- 任务中心整页接管筛选、分页和当前任务；全局摘要只负责查看和定位。接受、完成和待处理通知不替换当前报告；报告滚动和发起研究草稿分别保存。
- 概览、资料准备、模型研究、诊断独立组织。任务切换先清除旧动作；模型、上传和预算恢复按任务／修订／计划绑定，远端结果未知时不自动重发。阶段性研究不使用完整完成状态。
- 现有后台列表修订驱动当前服务端页读取；每次至多读取当前 50 条，不按已有首屏猜测后续页，不新增轮询时钟。同一查询的慢响应期间合并更新，翻页或改筛选时丢弃迟到的旧查询。
- 保持报告正文样式；页面与弹出摘要采用独立布局，窄屏列表/详情切换，高缩放不靠压缩字号。Windows 启动时按显示器工作区限制初始窗口大小，不修改系统 DPI 或用户配置。

| 界面复核 | 修正 | 理由 |
| --- | --- | --- |
| 全局长进度挤压正文 | 页头轻量摘要、任务详情独立滚动 | 读报告与后台研究可同时进行 |
| 窄窗口侧栏出现横向滚动条 | 保留竖向滚动并压缩导航边距 | 图标和焦点边框可达，避免横向拉动 |
| 同一首屏身份掩盖第二页变化 | 当前页单独读取并合并慢请求期间的修订 | 不用旧页混入新快照，也不重查全部历史 |
