# OpenThesis 2.0.0 版本更新规划：OT 生态与模型基础设施重构

> 状态：已获用户批准，正在实施与验收  
> 规划日期：2026-08-23  
> 实施验收日期：2026-08-24  
> 当前代码基线：OpenThesis 1.5.1  
> 目标版本：OpenThesis 2.0.0  
> 关联研究：[模型配置与密钥安全研究](../research/model-configuration-security-2.0.md)

## 一、版本定位

OpenThesis 2.0.0 不是一次普通页面改版，而是两项基础设施工程的合并升级：

1. 用新的 `.ot` 开放格式取代面向用户的旧 `.othesis` 研究包入口，建立可验证、可组合、可迁移的 OT 生态。
2. 彻底重构模型目录、模型连接、密钥保存、模型调用和任务选模流程，建立统一的“模型中心”。

原 `1.6.0.md` 中尚未实施的 OT 规划全部并入 2.0.0，1.6.0 不再作为独立目标版本实施。旧文档保留为决策历史，2.0.0 是后续实现和验收的唯一依据。

用户已经明确批准本规划并授权实施。当前阶段按本文逐项完成代码、自动化测试、人工界面与真实流程验收；在用户测试本地发行包并再次授权前，不提交、不推送、不发布 GitHub Release。

## 二、2.0 核心原则

### 2.1 模型不是安装包内容

- OpenThesis 不内置任何模型权重。
- OpenThesis 不内置、静默下载或自动安装 Ollama。
- 安装包中不包含“演示模型”、隐藏模型缓存或首次启动自动拉取脚本。
- OpenThesis 只检测并连接用户电脑上已经存在、已经启动的 Ollama。
- 云端模型通过用户自己的账号和凭据连接。
- 2.0 的体积增长只来自必要的界面、协议、安全库和适配器，不来自模型或推理运行时。

### 2.2 配置一次，按本机安全边界长期保留

- 用户不再每次打开软件或开始研究时重新输入 API Key（应用程序接口密钥）。
- API Key 保存在当前操作系统用户的系统凭据库中，而不是明文配置、SQLite、`.ot`、研究记录或日志。
- “长期保留”表示跨应用重启可用，不承诺在系统重装、换电脑、用户密码被管理员重置或凭据库损坏后仍可恢复。
- 默认不导出 API Key；导出 `.ot`、研究报告和普通设置备份时绝不包含密钥。

### 2.3 模型配置与任务发起解耦

- 所有 Provider（模型服务商）、账户、Endpoint（接口地址）、API Key、模型发现和连接测试统一在“模型中心”完成。
- 新研究页不再出现 Provider、Endpoint、API Key 或刷新模型字段。
- 新研究页只显示已经配置、启用且可用的模型。
- OT 创作工作室的辅助模型选择器遵守同一规则。
- 如果没有可用模型，任务页显示明确空状态并跳转模型中心，不临时弹出密钥表单。

### 2.4 一个目录，多种连接，多个模型

- 应用自带一个可离线使用的 Provider Registry（服务商注册表）。
- 保留在线模型刷新能力：模型中心按用户已保存的连接向对应 Provider 发现账户可用模型；Provider Registry 本身随签名应用版本发布，不接受运行时远端代码或策略更新。
- 同一 Provider 可配置多个账户或多个区域连接。
- 同一连接可启用一个或多个模型。
- 用户可为不同任务保存模型组合，但系统不得未经允许随机切换 Provider 或从免费模型静默切换到收费模型。

### 2.5 免费必须准确、可解释、可失效

- `Free（免费）`角标只表示当前已验证的模型或调用路径具备免费额度或不收取云端推理费，不代表无限、永久或没有任何成本。
- 本地 Ollama 可显示 `Free（免费）`，同时注明仍消耗用户自己的硬件、电力并受模型许可证约束。
- 有免费额度的云端 Provider 只在具体免费模型或免费路由上显示角标，不能把整个 Provider 错标为免费。
- 免费状态必须记录来源、最后核对时间和可能变化的提示。
- 遇到额度耗尽、限流或免费模型下线时明确报错，不自动切换到收费模型。

### 2.6 `.ot` 不携带秘密

- `.ot` 文件只能引用模型角色、能力要求或用户本机的配置别名，不能包含 API Key。
- 分享 `.ot` 时，接收者用自己的本机模型配置解析角色要求。
- OT 生态与模型生态通过稳定 ID 和能力声明连接，不通过复制密钥或写死本机路径连接。

## 三、当前实现基线与重构原因

当前代码已经具备一些可迁移基础，但职责混合严重：

- `src/openthesis/model_catalog.py` 内置 DeepSeek、Qwen、Kimi、GLM、OpenAI、Gemini、OpenRouter、Ollama 和自定义 OpenAI-compatible（兼容 OpenAI 接口）预设。
- 当前已有在线模型发现、连接测试和 Ollama 模型探测。
- `desktop/src/features/research/NewResearchView.tsx` 仍在每次研究时收集 Provider、模型、Endpoint、超时和 API Key。
- `desktop/src/types.ts`、`desktop/src/protocol.ts` 和 Python 服务协议仍直接携带 `api_key`。
- 当前文档和测试明确要求密钥只在当前会话存在；2.0 将有意识地替换这一旧约束，同时保留“不记录、不回显、不进入研究快照”的安全要求。
- `desktop/src/features/settings/SettingsView.tsx` 当前只有语言设置，不是统一模型配置中心。
- 旧 Tk 界面 `src/openthesis/app.py` 也持有一套模型和 API Key 表单，形成重复实现。
- 研究主模型、比较模型、视觉识别模型和文档提取 Token 目前存在不同配置入口，需要统一成“连接 + 已配置模型 + 任务角色”的结构。

2.0 不在旧 `ModelSelection` 上增加“记住密钥”复选框，而是拆掉上述耦合，重新定义完整模型域。

## 四、明确不做的事情

- 不内置 Ollama。
- 不内置模型文件或模型下载器。
- 不把第三方网页中的大量 AI 应用图标照搬进 OpenThesis。
- 不显示尚未实现适配器的 Provider 卡片来制造“支持很多模型”的假象。
- 不将 API Key 存进 SQLite、JSON、YAML、`.env`、浏览器 Local Storage（本地存储）、命令行参数或普通环境变量。
- 不提供给前端调用的 `get_secret()`（读取明文密钥）接口。
- 不在 2.0 首发中提供包含秘密的云同步或跨设备备份。
- 不继续支持用户或第三方 `.othesis` 的打开、导入、安装、运行或通用转换。
- 不把 GitHub Models 作为免费模型入口；该服务已被 GitHub 官方标记为全面退役。

## 五、目标架构

```text
模型中心（React / TypeScript 前端）
  ├─ Provider 图标网格、搜索、筛选和帮助
  ├─ 账户与 Endpoint 非秘密配置
  ├─ API Key 只在保存/替换瞬间输入
  └─ 已配置模型、能力、Free 状态和健康状态
                │
                │ 最小权限 Tauri Command（Tauri 命令）
                ▼
Rust Model & Secret Broker（模型与密钥代理）
  ├─ CredentialVault：系统凭据库
  ├─ ProviderRegistry：随应用发布的内置安全目录
  ├─ ModelGateway：连接测试、模型发现和模型请求
  ├─ RequestPolicy：域名、协议、能力与费用策略
  └─ SecretRedaction：日志与错误脱敏
                │
                ├─ Windows Credential Manager：只存秘密
                ├─ SQLite：只存非秘密元数据和 credential_ref
                └─ 私有本地 IPC：向 Python 提供无密钥模型调用
                                   │
                                   ▼
Python 研究核心
  ├─ 财务、业务、风险、综合和验证流程
  ├─ 只提交 configured_model_id 与推理请求
  └─ 不读取或持久保存长期 API Key

研究页 / OT 创作工作室
  └─ 复用同一个“已配置模型选择器”
```

正式 2.0 发行构建中的云模型请求由 Rust `ModelGateway（模型网关）`读取系统凭据并发出。Python 研究核心通过私有本地通道提交不含密钥的推理请求。

迁移开发阶段可以暂时保留兼容桥，但密钥只能通过受限匿名管道或私有命名管道短暂进入 Python 内存；不得经过命令行、环境变量、临时文件、普通 JSON 日志或研究快照。兼容桥不能成为 2.0 正式发行的最终安全边界。

## 六、模型域重新建模

### 6.1 ProviderDefinition（服务商定义）

表示应用支持什么，不表示用户已经配置什么。建议字段：

```text
provider_id
display_name
regions
protocol_adapter
built_in_endpoints
allowed_hosts
auth_schema
supports_model_discovery
capability_hints
registration_guide
credential_guide
brand_asset_id
catalog_version
deprecated
```

Provider 定义属于签名应用版本内置目录，不能保存用户密钥；2.0 的在线刷新只发现连接可用模型，不远程替换 Provider 安全策略。

### 6.2 ProviderConnection（服务商连接）

表示用户的一组可用账户或接口连接。建议字段：

```text
connection_id
provider_id
display_name
region
base_url
credential_ref
credential_version
enabled
status
last_tested_at
created_at
updated_at
```

同一个 Provider 可以有多个连接，例如个人账户、团队账户、中国区和全球区。`credential_ref` 只是系统凭据目标名，不是 API Key。

### 6.3 ConfiguredModel（已配置模型）

表示用户真正允许 OpenThesis 使用的具体模型。建议字段：

```text
configured_model_id
connection_id
provider_model_id
display_alias
capabilities
context_window_hint
billing_class
free_source_url
free_verified_at
enabled
health_status
last_discovered_at
```

`billing_class` 至少区分：

- `local_no_provider_fee`：本地运行，无云端 Provider 调用费；
- `free_tier`：云端免费额度；
- `paid`：收费；
- `unknown`：无法可靠判断。

### 6.4 ModelProfile（模型组合）

用于保存一次任务的模型角色，而不是复制连接信息。

```text
profile_id
display_name
primary_model_id
comparison_model_ids[]
verification_model_id?
vision_model_id?
fallback_policy
```

2.0 默认规则：

- 第一个模型是主模型；
- 用户可选零个或多个比较模型；
- 验证模型只有在用户明确设置后才独立调用；
- 默认不做收费回退；
- 每个实际调用的 Provider、模型、配置版本和参数写入研究运行记录，但不写密钥。

### 6.5 ModelCapability（模型能力）

能力声明至少覆盖：

- 文本对话；
- 结构化 JSON 输出；
- 视觉输入；
- 工具调用；
- 上下文长度提示；
- 是否适合 OT 小型辅助任务；
- 是否适合完整研究任务。

能力声明是筛选依据，不是质量保证。在线模型发现结果只能形成候选模型，不能越过本地 Provider 适配器、Endpoint 策略和连接测试。

## 七、独立“模型中心”页面

### 7.1 页面入口

- 在主导航增加一级页面“模型中心”。
- 首次启动且没有模型时，新手引导直接进入模型中心。
- 设置页只保留应用级设置；模型配置不再藏在普通设置的一个折叠区中。
- 研究页和 OT 创作工作室的空状态均可一键跳转模型中心，并在返回后恢复用户未提交的编辑状态。

### 7.2 页面信息架构

页面分为两个主要视图：

1. `服务商`：浏览应用支持的 Provider，完成连接和添加模型。
2. `我的模型`：查看、测试、排序、禁用、替换密钥和删除已配置模型。

顶部固定提供：

- 搜索框；
- `全部 / 已配置 / 免费可用 / 本地 / 云端`筛选；
- 每个连接中的“发现模型”；
- “添加自定义 OpenAI-compatible 连接”；
- 凭据库状态、连接状态和最近模型发现时间。

### 7.3 Provider 图标网格

参考用户提供图片的“图标 + 名称”网格，但不复制其中的软件集合和品牌资产。

每张卡片显示：

- 官方图标或许可明确的品牌图；没有合适资产时使用统一字母图标；
- Provider 名称；
- `已配置`、`需要配置`、`不可用`或`已弃用`状态；
- 已配置模型数量；
- 本地、云端或自定义类型；
- 仅在确有免费入口时显示右上角 `Free` 角标；
- 错误状态必须同时使用图标和文字，不能只靠颜色。

首发网格只呈现当前已有或 2.0 明确实现的适配器：

- OpenAI；
- DeepSeek；
- Qwen（通义千问）；
- Kimi（中国区/全球区在连接配置中选择）；
- GLM（智谱）；
- Gemini；
- OpenRouter；
- Ollama；
- 自定义 OpenAI-compatible Endpoint（兼容接口地址）。

Provider 适配器是否最终保留，以实现阶段对当前官方 API 的验证结果为准；失效服务必须被明确标记或删除，不能只保留图标。

### 7.4 卡片点击后的详情面板

点击 Provider 卡片打开靠近触发位置的详情面板，而不是跳进多层设置。面板顺序：

1. Provider 简介和数据会发送到哪里；
2. 免费/收费状态与最后核对时间；
3. 三步以内的注册说明和官方链接；
4. 账户显示名、区域、Endpoint 等非秘密字段；
5. API Key 密码输入框；
6. “保存并测试”主按钮；
7. 发现到的模型列表；
8. 勾选一个或多个模型并添加；
9. 高级选项和危险操作。

连接测试必须可取消。错误显示在相关字段附近，并提供可操作的分类：凭据错误、Endpoint 错误、网络错误、限流、免费额度耗尽、模型不存在或本地服务未运行。

### 7.5 多账户与多模型

- 一个 Provider 卡片可添加多个连接。
- 每个连接有用户可读别名，例如“个人 OpenRouter”或“本地工作站 Ollama”。
- 测试成功后允许多选模型并一次添加。
- 模型发现失败时允许手动填写模型 ID，但必须标记为“未验证”，测试通过前不进入研究选择器。
- 修改 Endpoint 会使旧测试状态失效，必须重新确认密钥发送目标并再次测试。

## 八、API Key 安全存储设计

### 8.1 Windows 首选方案

2.0 Windows 版使用 Windows Credential Manager（Windows 凭据管理器）的 Generic Credential（通用凭据）。建议目标名：

```text
OpenThesis/2/provider/{provider_id}/connection/{connection_id}/version/{credential_version}
```

- Rust 侧通过 `keyring-core` 和 Windows 原生凭据后端访问。
- 凭据按当前 Windows 用户保存，不使用机器全局范围。
- 不使用 `CRYPTPROTECT_LOCAL_MACHINE`，避免本机其他用户能够解密。
- DPAPI（Windows 数据保护 API）只作为 Windows 特殊环境的后备，不作为 SQLite 自制加密层。

### 8.2 前端密钥边界

- 密钥只在用户输入和调用受限 `save_secret` 命令的短时间内存在于前端内存。
- 保存成功或失败后清空输入字段，不写 React 持久状态、Local Storage 或历史表单。
- 页面只返回 `has_secret`、掩码尾部、版本和状态，不提供读取完整密钥功能。
- 默认只能“替换密钥”或“删除密钥”，不能点击眼睛图标永久显示旧密钥。
- 模型中心命令使用最小 Tauri Capability（能力权限），其他窗口和普通页面不能调用密钥写入接口。

### 8.3 Rust 密钥代理

Rust 侧至少提供：

```text
list_provider_metadata()              -> 非秘密元数据
list_connections()                    -> 非秘密状态与掩码
save_connection_secret(...)           -> 保存结果，不返回 secret
rotate_connection_secret(...)         -> 轮换结果
test_connection(connection_id)        -> 公开错误分类
delete_connection_secret(...)         -> 删除结果
list_configured_models()               -> 非秘密模型信息
invoke_model(configured_model_id, ...) -> 模型结果，不回显 secret
```

不得提供面向前端的 `read_secret()` 或通用“读取任意凭据目标”命令。

### 8.4 SQLite 存储边界

SQLite 只保存：

- Provider、连接和模型的非秘密元数据；
- `credential_ref`；
- 凭据版本；
- 健康状态和测试时间；
- 模型能力、费用类别和目录版本；
- 研究运行使用的非秘密配置快照。

SQLite 不保存：

- API Key；
- OAuth Refresh Token（刷新令牌）；
- Provider 密码；
- Stronghold 或其他保险库的主解锁密码；
- 可用于恢复完整密钥的明文或固定应用密钥。

### 8.5 轮换与删除

密钥轮换顺序：

```text
写入新版本凭据
  -> 使用新版本做最低成本测试
  -> 原子切换 active credential version（活动凭据版本）
  -> 停止向旧版本发出新请求
  -> 安全删除旧凭据
```

删除连接时先阻止新任务，再删除系统凭据，最后删除或停用 SQLite 元数据。任何一步失败都必须显示可恢复状态，不能留下“界面已删除但密钥仍存在”的假成功。

### 8.6 日志、错误与崩溃

- API Key 不进入 stdout、stderr、Tauri Event（事件）、研究日志、调试日志、错误消息和崩溃上下文。
- 常见 Header（请求头）如 `Authorization`、`x-api-key` 和 Provider 特有凭据字段统一脱敏。
- `Debug` 输出禁止自动打印含秘密结构。
- 连接测试只返回分类、状态码和清理后的短消息。
- 取消、超时、重试和 Provider 回显错误均执行相同脱敏规则。

## 九、Ollama 兼容方案

### 9.1 只连接已有安装

- 默认探测用户本机 `localhost:11434`。
- 优先使用 Ollama 官方 OpenAI-compatible Endpoint（兼容接口）`http://localhost:11434/v1/`和模型发现接口。
- 不查找或打包模型权重目录。
- 不执行 Ollama 安装器。
- 不自动执行 `ollama pull`。
- 不为 Ollama 保存虚假 API Key；兼容客户端若要求非空字段，只在运行时使用会被 Ollama 忽略的固定占位符。

### 9.2 状态设计

Ollama 卡片必须区分：

- 已检测到服务和已安装模型；
- 已检测到服务但没有可用模型；
- 未检测到服务；
- 用户主动配置了远程 Ollama。

未检测到时提供官方安装链接和简短说明，不代替用户下载安装。没有模型时提供可复制的官方命令示例，但不在后台执行。

### 9.3 隐私与远程地址

- `localhost` 和明确的回环地址可使用 HTTP。
- 非回环 Ollama 地址必须显示“数据将离开本机”的提示，并要求明确确认。
- 远程地址仍受 Host Allowlist（主机允许列表）、Endpoint 变更确认和防 SSRF（服务端请求伪造）检查。
- Ollama 的 `Free` 角标提示文本为“无云端调用费；仍消耗本机硬件和电力”。

## 十、免费模型与注册帮助

### 10.1 2.0 首发免费路径

首发至少提供两条不内置模型的零云端费用/免费额度路径：

1. 用户已安装的 Ollama：本地推理，无 OpenThesis 或云端模型调用费。
2. OpenRouter Free：使用官方免费路由或带 `:free` 的模型变体，额度、排队和可用模型会变化。

其他 Provider 的免费层只有在实现时从官方资料确认后，才能在目录中显示。不能因为 Provider 曾经有免费活动就永久打 `Free` 角标。

### 10.2 OpenRouter Free 行为

- 提供官方注册页和创建 API Key 的链接。
- 注册说明控制在三步以内，并建议用户设置清晰名称、过期时间和消费上限。
- 显示官方额度和可用性可能变化的提示，不把当前数值写成永久承诺。
- 免费模型返回 429、下线或额度耗尽时明确报告。
- 不静默转向收费模型，不自动充值，不替用户创建账户。

### 10.3 GitHub Models 迁移

- GitHub Models 已于 2026-07-30 被官方标记为全面退役。
- 旧 1.6 规划中的 GitHub Models 免费入口从 2.0 运行范围删除。
- 如果旧配置或实验代码中存在该 Provider，迁移后显示“服务已退役”，允许删除，不尝试继续调用。
- 未来 GitHub 推出替代服务时必须重新评估，不能复用旧凭据或假设旧 API 兼容。

### 10.4 免费状态的数据契约

免费标记必须包含：

```text
billing_class
source_url
verified_at
scope                # Provider、模型或路由
limit_summary
may_change
no_paid_fallback
```

过期或无法验证时降级为 `Unknown（未知）`，而不是继续显示 `Free`。

## 十一、内置目录与在线模型刷新

### 11.1 2.0 的刷新边界

2.0 只提供`刷新账户模型`：用户在某个已保存连接中点击“发现模型”，Rust Model Gateway（模型网关）按该连接的 Provider、Endpoint 和安全策略获取当前可用模型。

Provider Registry（服务商注册表）不在运行时从远端更新。Provider 展示、官方帮助、协议适配器、默认 Endpoint、允许域名和费用识别策略都随签名应用版本发布。这样保留用户要求的在线模型刷新，同时不引入一个可远程改变密钥发送边界的新供应链。

### 11.2 内置安全基线

- 安装包自带版本化 Provider 目录，离线仍能打开模型中心和查看注册说明。
- 目录包含稳定 Provider ID、协议适配器、官方 Endpoint、域名允许列表、字段 Schema（结构）和本地图标/标记。
- Provider 适配器和安全策略只能随应用版本更新，远端不能注入 JavaScript、Python、Rust 或 Prompt（提示词）代码。
- 模型发现失败时保留已有配置，并允许用户手动添加模型 ID；手动候选在测试前保持`未验证`。
- 发现结果不能扩大允许域名、关闭 HTTPS、改变 Tauri 权限或自动产生收费回退。
- 页面显示连接最近发现时间、测试状态和安全错误，不伪造“目录已更新”。

### 11.3 后续扩展

如果未来确需独立在线 Provider 目录，必须作为新的安全功能单独设计和验收，包括签名、版本回退保护、受限字段、可信来源和撤销机制；它不属于 2.0 首发运行时。

## 十二、研究发起流程重构

### 12.1 删除研究页中的连接配置

从新研究页移除：

- Provider 选择器；
- API Key 输入框；
- Endpoint 输入框；
- 账户级超时配置；
- 刷新模型按钮；
- Provider 注册帮助；
- 连接测试按钮。

这些功能全部移动到模型中心。

### 12.2 统一已配置模型选择器

研究页只保留“研究模型”区域：

- 单击下拉栏选择主模型；
- 可展开“添加比较模型”并多选；
- 只显示 `enabled + configured + policy_allowed` 的模型；
- 每项显示别名、模型 ID、Provider 和状态；
- 免费模型在末尾显示 `Free`；
- 本地模型额外显示 `Local（本地）`；
- 收费未知时显示 `Cost unknown（费用未知）`，不伪装免费；
- 键盘可搜索并按 Provider、能力和费用筛选。

建议显示格式：

```text
Research Mini — qwen3:8b (Ollama) · Local · Free
OpenRouter Free — openrouter/free (OpenRouter) · Free
Primary Model — model-id (Provider)
```

### 12.3 多模型语义

- 用户选择多个模型不代表每个 Agent 都调用所有模型。
- 主模型执行正常研究流程。
- 比较模型只用于当前代码已经定义的比较、复核或用户明确启用的角色。
- 每增加一个可能收费的模型，界面显示调用范围和费用提示。
- 模型不可用时暂停并要求用户选择，不做跨 Provider 隐式回退。
- 模型组合可以保存为 Profile（配置方案），但 Profile 只保存模型引用和参数。

### 12.4 运行可复现性

每次研究保存：

- Provider ID；
- Provider 连接的非秘密 ID；
- 模型 ID 和显示别名；
- 模型配置版本；
- Provider 目录版本；
- temperature（温度）、timeout（超时）和其他实际参数；
- 主模型、比较模型、验证模型的角色；
- 免费/收费分类快照及其核对时间。

绝不保存 API Key、系统凭据内容或可从快照恢复密钥的数据。

## 十三、OT 创作工作室与模型中心联动

2.0 继续建设独立的“OT 创作工作室”页面：

- 预览与 Diff（差异）：应用模型建议前显示具体改动，用户确认后才写入工作副本；

### 13.1 OT 辅助模型选择器

- 与研究页复用同一数据源和组件。

- 如果没有模型，仍允许全部手动编辑功能，并提供“前往模型中心”的可选入口。
- 小模型建议必须受字段范围、长度、Schema 和可修改路径限制。

## 十四、`.ot` 生态规划并入 2.0

以下原 1.6.0 决策保持不变并成为 2.0 验收范围：

- `.ot` 是新的正式扩展名。
- 2.0 不支持用户或第三方 `.othesis`。
- 项目自己维护的官方旧 `.othesis` 资源会在开发期由受控迁移工具一次性转换为官方 `.ot`。
- 转换器不进入用户运行时，不成为通用兼容层。
- 2.0 正式发行包只携带新官方 `.ot`。
- `.ot` 使用版本化 Schema、稳定 ID、确定性打包、哈希、权限声明、资源预算和兼容性声明。
- `.ot` 可承载研究流程、导出模板、确定性数据变换、验证规则和界面表单等受控包类型。
- `.ot` 不允许任意 Python、JavaScript、Shell、动态库或网络代码。
- `.ot` 默认无网络权限；需要网络的能力必须由受控 Connector（连接器）提供并经过明确授权。
- 建立官方 Registry（注册表）、Lockfile（锁文件）、依赖解析、签名、撤销和隔离验证边界。
- OT 创作工作室是普通用户和专业作者的共同入口。

2.0 的模型引用规则补充为：

- `.ot` 只声明能力，例如“需要支持 JSON 的辅助模型”，或引用本地 Profile 别名。
- `.ot` 不得指定或覆盖密钥发送地址。
- 外部 `.ot` 不能通过 Prompt 或配置要求读取系统凭据。
- `.ot` 安装、预览、导出和分享时执行秘密扫描。

## 十五、旧代码迁移与收敛

- 将 `model_catalog.py` 拆分为内置 Provider Registry、账户模型发现和费用元数据；2.0 不保留运行时远程 Provider 目录。
- 将 Python `ModelConfig.api_key` 和 Provider 直接持钥路径迁移到 Rust Model Gateway。
- 为 OpenAI-compatible、Gemini 和 Ollama 建立明确适配器接口。
- 保留当前模型发现和错误脱敏测试的有效语义，但请求参数改为 `connection_id` 或 `configured_model_id`。

### 15.2 协议

旧协议：

```text
ModelSelection {
  preset_id,
  model,
  base_url,
  api_key,
  timeout_seconds
}
```

新协议：

```text
ModelReference {
  configured_model_id,
  configuration_version,
  role
}
```

研究请求、重试综合、重试增长、视觉识别和 OT 辅助均不得再接受原始 `api_key`。

### 15.3 旧 Tk 界面

- 2.0 的用户可见模型配置只在 Tauri 桌面应用实现。

- 实施阶段先确认旧 Tk 是否仍属于正式发行入口；如果是，则迁移为只读兼容提示并引导 Tauri，随后从正式包移除。
- Python 研究核心继续保留，但界面层不保留重复模型中心。

### 15.4 视觉与文档提取配置

- 将当前视觉模型 API Key、MinerU Token 等秘密统一迁入连接模型。
- 按连接类别区分 `text`、`vision`、`document_extraction`，但复用 CredentialVault（凭据库）。
- 研究页只选择已配置视觉/提取连接，不再临时输入 Token。
- 数据上传同意仍按每次任务明确展示，保存密钥不等于用户永久同意上传文件。

## 十六、数据迁移

### 16.1 从 1.5.1 升级

当前稳定实现不持久保存 API Key，因此升级迁移只处理非秘密数据：

- 从旧 Provider、model、base_url、timeout 偏好生成“待确认连接草稿”；
- 不伪造已保存密钥；
- 用户第一次进入模型中心时补充密钥并测试；
- 旧研究历史继续可读，旧会话中的密钥字段在迁移中强制清空；
- 已保存的研究可显示历史模型字符串，但不能被当成当前可用连接。

### 16.2 `.othesis` 官方资源迁移

- 只转换仓库内由 OpenThesis 自己维护、内容和来源可核对的官方 Research Pack（研究包）。
- 转换建立固定映射表、源哈希、目标哈希和语义等价测试。
- 不扫描用户目录寻找 `.othesis`。
- 不显示“选择旧文件转换”的用户入口。
- 转换完成后，正式运行时删除旧解析和导入入口。

### 16.3 失败和回滚

- 数据库迁移先备份非秘密数据库。
- OS 凭据写入失败时不提交“已配置”元数据。
- 元数据提交失败时清理刚写入但未引用的凭据。
- 升级失败可以回到旧应用读取旧研究数据，但新系统凭据不回写旧版明文配置。
- 提供凭据孤儿扫描和用户确认后的清理工具，只处理 `OpenThesis/2/` 命名空间。

## 十七、安全网络策略

- 官方 Provider 只向内置允许域名发送凭据。
- 自定义 Endpoint 默认要求 HTTPS；回环地址允许 HTTP。
- 自定义域名首次保存和每次变更都显示完整 Origin（来源域）并要求确认。
- URL 解析后阻止意外协议、嵌入凭据、重定向到未授权域、DNS 重绑定和本地敏感网段访问。
- Provider 重定向不能携带 Authorization Header 到不同 Origin。
- 在线模型发现无权扩大 Credential Send Policy（凭据发送策略）或改变 Provider Endpoint 允许列表。
- 连接测试使用最低成本请求；禁止为测试运行完整研究。
- 401/403 标记凭据失效；429 标记限流；不得无上限自动重试。

## 十八、Emil 设计规范落地

模型中心按 Emil Kowalski 的设计工程原则实现克制、快速、可预测的交互。

### 18.1 动效

- 高频页面打开不做整片卡片逐个入场动画。
- 卡片按下使用约 `scale(0.97)`、100–160ms 的即时反馈。
- 详情面板和下拉栏使用 180–240ms 的自定义 ease-out（缓出）曲线，例如 `cubic-bezier(0.23, 1, 0.32, 1)`。
- 动画只作用于 `transform` 和 `opacity`，避免布局抖动。
- 鼠标悬停效果只在支持精细指针且确实可悬停的设备启用。
- 键盘导航触发的操作不附加位移动画。
- 完整支持 `prefers-reduced-motion（减少动态效果偏好）`。
- 不使用无限旋转图标表示长期连接；测试中使用可取消进度和明确文本。

### 18.2 空间与连续性

- 详情面板从被点击卡片的空间关系中出现，关闭后焦点回到原卡片。
- 从模型中心返回研究页时保留研究草稿、滚动位置和选择焦点。
- 下拉栏展开方向根据可用空间选择，避免超出窗口。
- 页面在 1366px 常见 Windows 屏幕、窄窗口和 200% 缩放下仍可用。

### 18.3 可用性

- 最常见路径控制为：点击 Provider → 填写密钥 → 保存并测试 → 选择模型 → 完成。
- Provider 特殊字段只在需要时出现。
- 好的默认值自动填入官方 Endpoint，用户不必理解 URL 才能完成配置。
- 复杂字段收进“高级设置”，但错误不会被藏在折叠区域。
- 危险操作使用清晰文案，删除密钥与禁用模型分开。
- 所有状态同时有文字、图标和可访问名称，不只依赖颜色或角标。

## 十九、国际化与文字规范

- 2.0 规划、Schema 说明和中文帮助以中文为主。
- 必须使用英文技术名时同时给出中文解释。

## 二十四、主要风险与处理

1. **工程体量**：模型网关、密钥库、OT 运行时和 OT Studio 同时变化。按阶段交付内部可验证切片，但最终统一按 2.0.0 验收。
2. **Python/Rust 边界**：完全避免 Python 接触长期密钥需要新的私有调用通道。先固定协议和威胁模型，再迁移 Provider，不能用命令行或环境变量图省事。
3. **操作系统限制**：Credential Manager 不能抵御已控制当前用户进程的恶意软件。文档明确威胁边界，并缩短明文在内存中的生命周期。
4. **免费服务变化**：免费额度和模型会变化。使用可过期元数据、来源和禁止收费回退，不在代码中承诺永久免费。
5. **模型发现投毒**：远端模型列表只作为候选，不能改变 Endpoint、域名或执行能力；手动/发现模型都必须经过本地连接测试才能用于研究。
6. **旧入口分叉**：Tk 和 Tauri 同时维护会重建双重状态。2.0 只保留一套用户模型中心。
7. **大版本迁移**：旧研究可读与新模型可用是两个概念。迁移历史字符串，但要求用户在模型中心重新建立安全连接。
