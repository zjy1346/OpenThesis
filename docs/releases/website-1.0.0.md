# OpenThesis Website 1.0.0 修改需求与验收清单

状态：**方案待用户批准，尚未实施**  
建立日期：2026-08-17  
规则：本文档是 OpenThesis 宣传网站 1.0.0 的需求与验收记录。用户明确批准本方案后才允许创建网站代码；完成后必须逐项验收，未验证项目不得标记完成。

## 1. 目标与边界

### 1.1 用户目标

- 在现有 OpenThesis 仓库中新增一个只承担宣传与产品介绍功能的网站。
- 视觉与滚动体验参考 `https://www.nanfu.global/` 的流畅、沉浸式滚动叙事，但不复制其品牌、内容或产品视觉。
- 宣传口径以用户最新确认的 OpenThesis 1.4.1 能力为准：美股、A 股、港股官方披露，证据优先，确定性财务计算，多 Agent 研究，严格财务质量门，可观察研究进度，模型自由与本地隐私边界。
- 1.4.1 重点能力必须被准确表达：下载、解析、校验和各 Agent 阶段具有真实进度；季度/中期同比只比较相同期间；增长机会与综合报告支持有效产物回退和针对性重试；失败状态与证据不足明确区分。
- 1.4 系列的可选云端财报识别只用于本地表格识别失败页，默认关闭，必须由用户明确同意并逐页批准；候选数据仍须通过同一财务质量门。
- 必须保证视觉完成度、动画流畅度和前端微交互细节。
- 需要真实产品画面时，由 Agent 启动本地 OpenThesis 应用并采集不含个人数据、API Key、SEC 联系信息或历史研究隐私的截图。
- 完成后进行浏览器动画与响应式检查，并向用户提供可在本机访问的预览页面。

### 1.2 本版本边界

- 网站不提供账户、在线研究、数据库、支付、评论或表单后台。
- 不修改 OpenThesis 桌面应用功能；网站代码独立放在 `website/`。
- 不上传域名、不发布 GitHub Pages、不提交、不推送，也不创建 GitHub Release；本轮只交付本地可检查版本。
- 下载按钮链接 GitHub Releases，安装包不复制进网站项目。
- 当前桌面端与本地便携构建版本为 1.4.1；截图以该版本真实界面为准，不使用未实现或尚未通过质量门的能力制造错误承诺。
- 不照搬参考站的代码、图片、视频、字体或品牌资产。

## 2. 实现位置与技术方案

### 2.1 独立网站工程

计划新增：

```text
website/
  package.json
  vite.config.ts
  index.html
  src/
  public/
  scripts/（如本地预览辅助脚本确有需要）
```

原则：

- 使用独立 Vite + React + TypeScript 工程，不复用或污染 `desktop/` 的构建配置与依赖。
- 使用 Motion 与 CSS 构建滚动进度、粘性舞台、视差、遮罩揭示和微交互。
- 默认保留浏览器原生滚动；不劫持滚轮，不强制滚动吸附，不依赖重型 3D/WebGL 才能阅读内容。
- 复杂效果优先使用真实应用截图、CSS 层叠、轻量遮罩和硬件加速变换；只有不可替代时才引入 Canvas。
- 构建产物为静态文件，并为后续 GitHub Pages 或 Cloudflare Pages 部署保留兼容性。

### 2.2 视觉系统

- 延续 OpenThesis 桌面应用的暖白、墨绿、深灰与浅绿色体系，同时增加适合沉浸首屏的深色章节。
- 视觉气质为“研究编辑部 / 证据工作台”，不使用常见 AI 光球、机器人、霓虹交易终端或投机型 K 线视觉。
- 标题采用紧凑无衬线字体；研究正文、引用和报告片段使用适合中英文阅读的衬线或正文系统字体。
- 使用细边框、低对比阴影、克制玻璃质感、真实报告表格和来源锚点建立可信度。
- 中文为默认语言，提供 English 切换；两种语言的主要叙事、导航、功能说明、边界说明和 CTA 均需完整。

## 3. 首页滚动叙事

### 3.1 固定导航

- 展示 OpenThesis 品牌、产品、研究流程、市场覆盖、隐私、GitHub 与下载入口。
- 导航随深浅章节切换对比度；桌面端保持清晰但不过度占用画面。
- 移动端使用可访问的紧凑菜单，触摸目标尺寸与键盘焦点状态完整。

### 3.2 第一幕：研究公司，而不是追逐价格

- 首屏使用大字号主张和简短产品定义。
- 背景以财报文本、数据片段和证券代码形成低频运动层。
- 滚动时噪声逐步退场，真实 OpenThesis 报告工作台进入中心舞台。
- 首要 CTA：下载 Windows 版；次要 CTA：查看 GitHub。

### 3.3 第二幕：一个工作台覆盖三个市场

- 通过粘性全屏章节依次展示 SEC、美股代码、A 股交易所与港交所披露来源。
- 使用 `AAPL`、`600519.SH`、`000001.SZ`、`832982.BJ`、`00700.HK` 等示例解释统一证券标识。
- 明确展示美股、上交所、深交所、北交所、港交所主板与 GEM。

### 3.4 第三幕：从官方披露到可追溯证据

- 固定一份财报/报告视觉，随滚动依次完成：原始披露、关键数据高亮、URL 与页码锚点、结构化财务表、缺失数据显式标记。
- 强调无法可靠识别的数据保持缺失，不由 AI 补写。
- 动画用于解释数据如何流动，不以装饰性循环抢夺阅读注意力。

### 3.5 第四幕：AI 研究，程序计算

- 财务、商业、会计风险、增长、质疑和验证 Agent 围绕同一组证据依次进入。
- 确定性财务计算与 Agent 推理使用不同视觉层级，避免暗示语言模型负责计算财务事实。
- 最终聚合成真实报告阅读器截图。

### 3.6 第五幕：研究过程真实可见

- 使用 1.4.1 的真实研究进度界面展示准备、披露查找、下载、解析、校验、财务分析、商业分析、风险、增长、反方审查、情景与综合阶段。
- 进度百分比、已用时间和子步骤保持单调、可解释；动画只呈现真实状态，不伪造剩余时间或用循环加载掩盖停滞。
- 展示部分报告与针对性重试：增长机会或综合阶段失败时只重试对应阶段，不重复下载财报或运行其他已完成 Agent。

### 3.7 第六幕：可复现的投资论点

- 以轻量关系图表现“证据 → 事实 → 推理 → 风险 → 情景 → 投资论点”。
- 展示报告历史、版本追踪与导出能力，不宣称买卖建议、收益率或短线预测。

### 3.8 隐私、开源与最终 CTA

- 明确 API Key 仅保留在当前会话、研究历史位于本机、首次启动默认不调用 AI。
- 提供 Apache-2.0、GitHub 源码、Windows 下载和投资建议免责声明。
- 金融机构研究 Beta、手动带日期市场价格、不抓实时行情等既有边界必须可见。
- 可选云端识图必须准确说明为“本地识别失败后的逐页授权兜底”，不得暗示默认上传整份财报，也不得淡化相同财务质量门。

## 4. 真实产品截图方案

计划采集并处理：

1. 新建公司研究 / 市场与证券选择。
2. 1.4.1 的真实研究阶段、已用时间、子步骤与多 Agent 进度。
3. 结构化报告阅读器与财务表格。
4. 阶段性报告、增长机会/综合报告针对性重试或投资论点版本界面。

截图约束：

- 优先运行离线合成演示或无敏感数据的公开公司示例。
- 截图前检查画面中没有 API Key、个人邮箱、机器路径、用户研究历史或其他本机隐私。
- 保留真实产品 UI，不伪造不存在的按钮、数据或能力。
- 输出 WebP/AVIF 等网页友好格式，按显示尺寸提供资源，避免原图直接造成加载和内存压力。
- 允许为构图裁剪和加入网页环境中的阴影/遮罩，但不得改变产品界面的含义。

## 5. Emil 前端与动效规范

| Before | After | Why |
| --- | --- | --- |
| 所有章节统一淡入 | 每段动画承担解释、空间连续性或反馈目的 | 避免动画变成无意义模板 |
| 动画布局属性、阴影和模糊同时变化 | 滚动主动画优先只改变 `transform`、`opacity`，必要时使用克制 `clip-path` | 减少重排和重绘，维持帧率 |
| 使用 `transition: all` | 明确列出需要过渡的属性 | 避免意外属性动画和调试困难 |
| 元素从 `scale(0)` 出现 | 使用接近原尺寸的缩放配合透明度 | 进入更自然，不产生凭空爆出的感觉 |
| 内置 `ease-in` 或线性 UI 过渡 | 进入使用强 ease-out，屏内移动使用 ease-in-out，持续运动才使用 linear | 响应更直接，运动更自然 |
| 所有设备播放相同复杂动画 | 桌面完整体验，触屏简化视差，`prefers-reduced-motion` 保留信息但移除大幅运动 | 保证可访问性与设备稳定性 |

具体约束：

- 按钮按下反馈为约 `scale(0.97)`，100–160ms。
- 普通 UI 反馈保持在约 125–250ms；长时间只用于用户主动滚动控制的解释性动画。
- 多元素入场错峰保持约 30–80ms，不用长延迟阻塞内容。
- hover 只在 `(hover: hover) and (pointer: fine)` 下启用。
- 动态交互优先使用可中断的 transition/spring；预定且独立的简单动画优先 CSS。
- 重复装饰动画在页面离开视口或标签页不可见时暂停。
- 不使用动画掩盖加载，不让导航、下载和阅读依赖动画完成。

## 6. 流畅度、响应式与质量验收

### 6.1 自动化与构建

- [ ] 网站依赖安装可复现，锁文件纳入版本控制。
- [ ] TypeScript 检查通过。
- [ ] 网站生产构建通过，静态资源路径可用于本地预览。
- [ ] 页面无阻塞性运行时错误、React 警告或重复控制台错误。
- [ ] 主要导航、语言切换、下载和 GitHub 链接可用且有可访问名称。

### 6.2 浏览器视觉验收

- [ ] 1440×900 桌面视口逐段滚动检查通过。
- [ ] 980×680 紧凑桌面视口无重叠、横向溢出或被固定层遮挡的正文。
- [ ] 390×844 移动视口可完整阅读并使用导航与 CTA。
- [ ] 普通动画模式和 `prefers-reduced-motion` 模式分别检查。
- [ ] 中英文切换不造成明显布局跳动、截断或不可达内容。
- [ ] 所有真实应用截图清晰、无隐私信息、无错误版本承诺。

### 6.3 动画流畅度验收

- [ ] 标准连续滚动下，固定章节没有可见抖动、闪烁、反向跳变或空白帧。
- [ ] 对滚动期间的 `requestAnimationFrame` 间隔进行测量并记录结果；检查持续长帧和明显掉帧区段。
- [ ] 主滚动动画只使用适合合成的属性；审查并移除滚动期间高频布局读取/写入。
- [ ] 图片、视频和字体不会在进入章节时造成明显的主线程停顿或布局偏移。
- [ ] 快速反向滚动时动画可中断并正确反向，不从错误初始状态重新播放。
- [ ] 在低动效与移动降级模式下，内容顺序和信息完整性不依赖动画。

### 6.4 人工体验验收

- [ ] 首屏在十秒内清楚说明 OpenThesis 是什么、覆盖哪些市场、又不是什么。
- [ ] 滚动叙事能解释产品流程，而不是只展示装饰性动效。
- [ ] 视觉语言与桌面应用一致，并明显区别于投机型交易网站。
- [ ] 免责声明、1.4.1 的云端识图授权边界、金融机构 Beta 与市场数据边界清晰但不压过产品主线。
- [ ] 最终 CTA 明确指向 Windows 下载与 GitHub。

## 7. 本地交付

- 完成后保留一个运行中的本地预览地址供用户立即检查。
- 同时提供一条简短、可重复执行的本地启动方式，用户关闭预览后仍能重新打开。
- 交付说明列出网站位置、预览地址、已完成检查、已知设备限制和尚未执行的线上域名部署。
- 只有用户完成本地检查并明确授权后，才讨论提交、推送、域名绑定或公开发布。
