状态：**已实施并完成本地验收，等待用户检查本地预览**  
建立日期：2026-08-17  
取代：`website-1.0.0.md` 的未实施方案  
规则：本文档是 OpenThesis 宣传网站 1.1.0 的需求与验收记录。用户明确批准本方案后才允许创建网站代码；完成后必须逐项验收，未验证项目不得标记完成。

## 1. 修正后的产品目标

### 1.1 网站介绍什么

- 网站介绍的是 **OpenThesis 1.4.1 当前能够完成的整体产品能力**，不是 1.4.1 更新日志，也不以“这一版修复了什么”为叙事中心。
- 网站应先完整盘点 1.4.1 的全部主要功能，再从中选择最能体现差异化、最适合视觉讲述的重点能力进行宣传。
- 页面不按内部模块罗列功能，而围绕用户路径讲述：选择真实公司 → 获取官方披露 → 校验财务证据 → 多 Agent 研究 → 阅读报告 → 更新投资论点。
- 参考 `https://www.nanfu.global/` 的沉浸式滚动、固定舞台、滚动进度和视觉节奏，但品牌、产品内容和研究语义必须属于 OpenThesis。
- 网站只提供宣传、介绍、下载和 GitHub 导流，不提供在线研究、账户、支付、数据库或投资交易。

### 1.2 产品定位

推荐主张：

> 研究公司，而不是追逐价格。

推荐产品定义：

> OpenThesis 是面向个人长期投资者的开源公司研究工作台。它将美股、A 股与港股官方披露、严格财务校验、确定性计算和专业 AI Agent 组织成可追溯、可复现的投资论点。

边界必须始终准确：

- 不连接券商账户，不执行交易，不提供短线信号。
- 不承诺投资收益，不使用“买入/卖出”式结论作为宣传卖点。
- 不抓取实时行情；市场价格或市值由用户输入并记录日期与币种。
- 识别不到的数据保持缺失，不能由模型补写。
- 金融机构研究为 Beta，不套用普通企业自由现金流反向 DCF。

## 2. OpenThesis 1.4.1 完整能力盘点

本节用于确保网站文案不遗漏或虚构能力。首页不要求逐条等量展示，应按第 3 节提炼重点。

### 2.1 市场、公司与官方披露

- 支持美股、A 股与港股研究入口。
- 美股通过 SEC EDGAR 与 XBRL 获取官方披露。
- A 股覆盖上交所、深交所与北交所，通过巨潮资讯等官方披露入口获取财报。
- 港股覆盖港交所主板与 GEM，通过披露易获取官方财报。
- 统一识别 `AAPL`、`600519.SH`、`000001.SZ`、`832982.BJ`、`00700.HK` 等证券代码。
- 区分发行人和上市证券，保存市场、交易所、上市币种、报告币种、会计准则、行业与支持等级。
- 支持真实公司搜索、常用公司快捷入口和官方披露页面跳转。

### 2.2 财报摄取、证据与财务质量门

- 下载并处理官方财报、财务表格和 XBRL/官方 PDF 数据。
- 财务事实保留来源 URL、报告页码、证据摘录、期间、单位、口径和币种。
- 本地识别结果必须经过期间、合并范围、会计口径、币种和勾稽关系校验。
- 无法通过质量门的数据被拒绝或隔离，不进入确定性财务计算。
- Q1、H1、Q3 等期间只与上一年度相同期间比较，禁止将季度累计值与完整财年混算。
- 缺少上一年同期官方披露时显示明确缺口，不伪造同比增长率。
- 发行/上市币种与报告币种在界面和报告中明确区分。

### 2.3 可选云端财报识别兜底

- 云端识图默认关闭，仅在本地表格识别失败后作为兜底。
- 用户必须先启用并同意，实际上传前还需要对失败页面进行明确审批。
- 只允许上传待补充识别的失败财务表页，不默认上传整份财报。
- 支持 MinerU Lite、MinerU Precision 和自定义视觉接口配置。
- 云端候选数据仍必须通过相同财务质量门；失败候选保留隔离审计状态。
- 网站不得把该能力描述成“自动上传财报”或弱化用户批准与质量校验边界。

### 2.4 确定性财务分析与估值

- 生成结构化财务概览和跨期财务表现分析。
- 由程序计算核心指标、增长率和反向 DCF，不把财务运算交给语言模型自由生成。
- 支持用户输入带日期和币种的市场价格、市值、折现率及终值增长率。
- 估值前检查报告币种与市场数据币种；币种不一致且没有可靠换算时不强行估值。
- 金融机构使用独立的 Beta 支持边界，不应用普通企业自由现金流反向 DCF。

### 2.5 模型自由与连接控制

- 支持 DeepSeek、Qwen、Kimi、GLM、OpenAI、Gemini、OpenRouter、Ollama 与任意 OpenAI-compatible 接口。
- 内置推荐模型目录，并可由用户主动刷新在线模型列表。
- 支持自定义模型 ID、接口地址和 API Key。
- 支持在开始研究前测试模型连接。
- 支持不调用 AI 的确定性模式。
- 支持选择第二模型进行对比研究。
- 支持最多两个基础 Agent 并行执行，临时失败只重试失败任务。

### 2.6 专业 Agent 研究流程

- 财务分析 Agent。
- 商业模式与竞争位置 Agent。
- 会计风险与质量审查 Agent。
- 增长机会 Agent。
- 反方/质疑 Agent。
- 长期情景与预测 Agent。
- 综合研究 Agent。
- 证据与数值验证流程。
- Agent 围绕同一组受控证据工作，不依靠无限制聊天历史。
- 最终报告保留证据、假设、反面观点、情景、风险和失效条件。

### 2.7 真实可观察的研究运行

- 研究过程包含稳定的准备、公司信息、披露发现、下载、解析、校验、财务、商业、风险、增长、反方、情景、综合和模型对比阶段。
- 显示真实阶段标题、子步骤、完成比例与已用时间，进度单调不回退。
- 显示各 Agent 的排队、运行、重试、完成、失败或取消状态。
- 支持研究取消，并安全保留已经完成的阶段。
- 启动时恢复上次异常中断研究的可见状态。
- 云端识图等待审批、处理中、失败和用户拒绝均有独立状态。
- 等待文案不能替代真实技术状态，也不伪造剩余时间。

### 2.8 部分报告、失败说明与针对性恢复

- 最终综合尚未完成时可以展示已完成阶段形成的部分报告。
- 综合报告失败时支持只重试综合阶段。
- 增长机会为空或模型返回无效内容时，优先使用已经保存且通过结构校验的独立增长研究产物。
- 增长机会阶段失败时支持只重试增长机会与后续综合，不重复下载财报或运行其他已完成 Agent。
- 模型空响应、结构无效、证据验证失败与确实证据不足使用不同状态，不用统一占位文案掩盖错误。

### 2.9 报告阅读与导出

- 现代结构化报告阅读器显示财务表格、指标、研究章节、证据提示和增长机会。
- 可切换技术详情，查看 Evidence ID、Agent ID 与研究元数据。
- 支持 90%–130% 报告缩放、按钮、键盘快捷键和 Ctrl 组合键。
- 支持沉浸式报告阅读，`F11` 进入/退出、`Esc` 返回。
- 支持将报告导出为独立 HTML、Markdown 或纯文本。
- 报告清楚显示市场、交易所、上市币种、报告币种、研究运行 ID 与免责声明。
- 支持简体中文或英文研究报告输出。

### 2.10 历史、投资论点与可复现性

- 本地保存研究历史，可重新打开报告、刷新列表和删除指定研究。
- 研究运行记录模型、参数、研究模块、数据快照、报告语言与应用版本。
- 投资论点采用追加式版本保存；用户编辑产生新版本，不覆盖旧版本。
- 可查看、编辑并保存结构化投资论点 JSON。
- 新财报和新判断可以形成新的论点版本，保留历史变化。

### 2.11 研究模块与开放扩展

- 内置官方长期基本面研究模块。
- 支持导入声明式 `.othesis` 研究模块。
- 模块可定义研究问题、提示词、流程、证据等级、规则和输出结构。
- 模块不需要分发任意可执行 Python/JavaScript 代码即可扩展研究流程。

### 2.12 本地优先、隐私与桌面体验

- Windows x64 便携版，解压后运行，不要求安装账户系统。
- 首次启动默认不调用 AI；提供离线合成演示功能，但网站产品截图不得使用合成演示公司。
- API Key 只保留在当前会话内存，不写入 SQLite、设置、报告或日志。
- SEC 联系信息与研究历史保存在用户本机，不进入发布包。
- 支持中英文界面，并可独立选择研究报告语言。
- 内置离线帮助、设置、架构诊断与模型帮助链接。
- Apache License 2.0 开源。

## 3. 首页重点宣传选择

完整能力不等于首页平均罗列。首版只把以下六组能力作为主叙事，其余能力进入支持性功能矩阵或页尾说明。

### 3.1 重点一：三大市场，一个研究工作台

- 核心信息：美股、A 股、港股统一入口，但保留各市场的交易所、币种、会计准则和披露差异。
- 视觉表达：`AAPL`、`600519.SH`、`832982.BJ`、`00700.HK` 从不同官方披露来源汇入同一工作台。

### 3.2 重点二：先证据，后观点

- 核心信息：官方财报、页码和来源锚点先通过质量门，再进入分析；识别不到就保持缺失。
- 视觉表达：真实财报页面 → 数据高亮 → 来源/页码 → 质量门 → 结构化财务表。

### 3.3 重点三：AI 负责研究，程序负责计算

- 核心信息：专业 Agent 分工研究，财务指标、期间同比与反向 DCF 由确定性程序计算。
- 视觉表达：Agent 在报告外层展开观点，数值在独立计算轨道中形成，最后汇入报告。

### 3.4 重点四：漫长研究过程，每一步都可见

- 核心信息：下载、解析、校验和各 Agent 阶段具有真实进度、已用时间、取消与失败状态。
- 视觉表达：使用 1.4.1 的真实进度界面，并将滚动叙事映射到研究阶段推进。

### 3.5 重点五：失败不伪装，研究可恢复

- 核心信息：部分报告、明确失败原因、增长机会/综合报告针对性重试，不重复已经完成的昂贵步骤。
- 视觉表达：完整报告暂未形成时，已完成章节保持可读；缺失模块经针对性重试补入。

### 3.6 重点六：你的模型，你的研究历史

- 核心信息：模型自由、本地优先、会话级密钥、可复现运行与追加式投资论点版本。
- 视觉表达：模型入口围绕本地工作台排列，研究产物最终进入本地历史和版本时间线。

## 5. 真实公司截图要求

### 5.1 禁止合成演示截图

- 网站中的所有 OpenThesis 产品截图必须来自真实上市公司研究。
- 不得使用 Synthetic Demo、虚构公司、示例财务数字或把合成报告裁剪成真实公司外观。
- 离线合成演示可以作为文字列出的产品能力，但不进入任何截图、视频或社交分享图。

### 5.2 推荐截图对象

- 中文与英文产品截图实际使用比亚迪港股 `01211.HK`，来自港交所官方披露与 OpenThesis 1.4.1 确定性引擎的真实研究运行。
- 英文界面使用同一真实公司的英文报告与研究阶段界面，没有回退到合成演示。
- 多市场章节可以使用真实证券代码与公开披露来源，但不得通过拼接伪造一份不存在的跨公司报告。

### 5.3 隐私与真实性

- 截图前清除或遮挡 API Key、视觉 Token、SEC 联系邮箱、机器路径、内部运行凭证和其他用户隐私。
- 不遮挡公司名称、证券代码、市场、报告币种、真实阶段和公开财务信息。
- 允许裁剪、透视、圆角、阴影、遮罩与网页背景合成；不得改变按钮含义、伪造完成状态或修改财务数字。
- 采用 WebP/AVIF，并为实际显示尺寸准备资源，避免超大截图导致卡顿。

## 6. 自动语言选择

### 6.1 初次访问规则

- 读取 `navigator.languages`，必要时回退到 `navigator.language`。
- 任一首选语言以 `zh` 开头时，初始打开中文界面，包括但不限于 `zh-CN`、`zh-SG`、`zh-TW`、`zh-HK`、`zh-Hans`、`zh-Hant`。
- 英语及所有其他语言默认打开 English，包括但不限于 `en-*`、日语、韩语、法语、德语、西班牙语、俄语和未识别语言。
- 中文界面首版统一使用简体中文文案；繁体中文系统不单独维护一套繁体翻译，但会进入中文界面。

### 6.2 无闪烁初始化

- 在应用渲染前完成语言解析，设置 `<html lang="zh-CN">` 或 `<html lang="en">`。
- 首屏不得先显示英文再跳中文，或先显示中文再跳英文。
- 中文与英文内容随网站静态资源一起提供，不依赖运行时翻译服务。

### 6.3 手动切换与记忆

- 导航提供中文 / English 手动切换。
- 用户手动选择后，将明确偏好保存在浏览器本地；后续访问优先使用用户选择，而不是再次覆盖为系统语言。
- 提供恢复“跟随系统语言”的方式，或在清除本地偏好后重新自动判断。
- 切换语言时不重置滚动位置，不重新播放整段首屏动画，不产生明显布局闪烁。

## 7. 允许复用源码的规则

### 7.1 可以直接复用

- MIT、BSD、Apache-2.0、ISC 等与项目兼容的开源库、示例和项目代码。
- GSAP、Motion、Lenis 或其他动画工具只在其当前许可证允许本项目使用时引入。
- 复用代码时保留许可证、版权声明和必要归属；需要时新增 `website/THIRD_PARTY_NOTICES.md`。
- 优先复用成熟的滚动、可访问性、焦点、响应式和性能实现，不重复制造低质量轮子。

### 7.2 不直接复制

- 参考商业网站未声明开源许可证的压缩 JavaScript、CSS、图片、视频、字体、三维模型和品牌素材。
- 无法确认授权来源的代码片段或素材。
- 与 OpenThesis 无关且会显著增加包体、追踪或安全风险的模板代码。

### 7.3 参考站使用方式

- 可以分析其粘性章节、滚动进度、横向映射、视频/Canvas 分层和导航状态。
- 对未授权实现采用等效重写，不复制其表达、资产或可识别代码结构。
- 任何引入的第三方源码都要在最终验收中列出来源、许可证、实际用途和是否修改。

## 8. 技术与视觉方案

### 8.1 工程位置

计划新增独立 `website/` 项目，不修改 `desktop/` 的构建配置：

```text
website/
  package.json
  vite.config.ts
  index.html
  src/
  public/
  THIRD_PARTY_NOTICES.md（存在第三方代码复用时）
```

### 8.2 动画实现

- 使用 Vite + React + TypeScript。
- 使用 Motion/CSS 构建滚动进度、粘性舞台、视差、遮罩揭示和可中断微交互。
- 默认保留浏览器原生滚动；不劫持滚轮，不强制滚动吸附。
- 滚动高频动画优先只改变 `transform` 与 `opacity`，必要时使用克制的 `clip-path`。
- 不使用 `transition: all`，不从 `scale(0)` 入场，不在滚动期间高频修改布局属性。
- 普通 UI 反馈控制在约 125–250ms；按钮按下约 `scale(0.97)`、100–160ms。
- hover 只在 `(hover: hover) and (pointer: fine)` 下启用。
- `prefers-reduced-motion` 保留内容与短透明度反馈，移除大幅位移、视差和持续装饰运动。
- 快速反向滚动时动画必须可中断、可反向，不从错误起点重播。

### 8.3 视觉系统

- 继承 OpenThesis 暖白、墨绿、深灰和浅绿色品牌体系，穿插一至两个深色沉浸章节。

- 使用真实报告、财务表、证据锚点、研究阶段和投资论点版本形成视觉资产。
- 避免为了华丽而使用高成本 3D；首屏或核心舞台确有必要时才使用 Canvas/WebGL。
