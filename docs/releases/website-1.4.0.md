## 1. 用户要求

- 移动端不能继续保持完全静态，需要加入与桌面端视觉语言一致的高级滚动动效。
- 移动端动效必须针对性能精简，不能直接复制桌面端高成本的长距离 pinned 时间线。
- 项目已经加入 `.ot` 生态，需要为 `.ot` 单独设计一个新页面。
- `.ot` 页面沿用现有官网的黑色、珊瑚色、真实研究感与滚动叙事方案。
- `.ot` 没有可用于官网的实际产品截图；新页面必须采用无截图设计，不得伪造应用界面或合成演示公司。
- 全站按照 OpenThesis 2.0 已上线结果表述，不使用计划状态、未来承诺或未交付暗示。
- 用户已明确授权提交、推送并触发 GitHub Pages 部署。

## 2. 当前实现与问题定位

### 2.1 移动端动画缺失

- 当前桌面端动画集中在 `website/src/motion/storyTimeline.ts`，通过 GSAP ScrollTrigger、长距离 story film 和 pinned 场景进行滚动叙事。
- `980px` 以下不挂载桌面时间线，`website/src/styles.css` 又将各场景强制恢复为普通文档流、完全可见且无变换，因此移动端几乎没有章节级动画。
- 这能避免桌面时间线在手机上造成卡顿，但也同时移除了层级、连续性和反馈，导致移动端明显失去官网的高级感。

### 2.2 `.ot` 页面缺少表达载体

- `.ot` 已是 OpenThesis 2.0 的正式生态能力，但目前没有可用于官网宣传的真实应用截图。
- 如果直接制作伪界面截图，会违反此前“截图必须真实”的要求。
- 新页面把正式文档与数据结构中的 `.ot` 能力转译为原生 SVG、排版、结构图和文件形态动画；概念结构图不伪装成产品界面。

## 3. 设计原则

本轮实施同时遵守 Apple Design 与 Emil Design Engineering 的以下约束：

- **Purpose**：每段动画必须说明空间关系、流程或层级，不添加无意义漂浮、旋转和装饰线。
- **Spatial consistency**：元素从自身或触发来源出现；桌面与移动端表达同一关系，只调整布局和运动幅度。
- **Interruptibility**：滚动动画由用户滚动位置控制，可前进、后退和中断，不设置阻塞式自动播放。
- **Performance**：主要动画只使用 `transform`、`opacity` 和 SVG `stroke-dashoffset`；不动画模糊、滤镜、阴影或布局属性。
- **Restraint**：每个移动端视口只设置一个主运动焦点，其余元素使用轻量伴随反馈。
- **Accessibility**：`prefers-reduced-motion` 下移除位移、缩放和路径绘制，只保留清晰的静态终态。

## 4. 移动端动效方案

### 4.1 动画架构

- 新增独立的移动端 motion controller，与桌面 `mountStoryTimeline` 分离，避免一个时间线同时承担两套行为。
- 保持普通文档流，不 pin 整页，不制造 700 屏高度，不让场景相互绝对叠放。
- 每章使用局部 ScrollTrigger：进入视口时完成主视觉揭示，继续滚动时仅做小幅视差或进度变化；离开后不持续占用动画资源。
- 使用独立 `matchMedia` 上下文管理桌面、移动端与 reduced-motion 三种状态，并在尺寸变化时完整清理与重建。

### 4.2 动效编排

- Hero：背景产品画面轻微纵向视差，主标题与 CTA 采用短距离、同方向层级进入；不使用弹跳。
- 市场：轨道路径逐段绘制，市场标签依次出现；移动幅度小于桌面端，避免边缘裁切。
- 证据：真实截图采用遮罩揭示，“证据来源”焦点卡从截图底边锚定出现，不改变裁切目标。
- Agents：真实窗口分层进入，连接路径在主卡可见后绘制，合并结果最后出现。
- 研究过程：报告先出现，实时进度卡从其下方进入；保持 1 主 1 辅，不重新引入时间线堆叠。
- 恢复与本地：失败状态、恢复路径、本地模型与历史卡按因果顺序出现，不使用随机角度。
- 能力清单与 CTA：按行短促 stagger，数量较多时使用批次揭示，避免同时启动大量 tween。

### 4.3 性能预算

- 手机端文案与细节位移控制在约 `8–22px`，场景容器最大位移 `28px`，缩放保持在 `0.975–1` 范围。
- 单个章节同时运行的 tween 数量保持克制；离屏章节不持续更新。
- 不对 `backdrop-filter`、`box-shadow`、宽高、top/left 或复杂 clip-path 做逐帧动画。
- SVG 仅绘制必要路径，移动端减少次级路径和装饰节点。
- 验收设备宽度至少覆盖 `390 × 844` 与 `430 × 932`，同时检查低端模式与快速连续滚动。

## 5. `.ot` 生态新页面

### 5.1 路由与发布方式

- 目标路径为 `https://openthesis.cc.cd/ot/`。
- 使用 Vite 多页面入口或等价的静态输出生成真实 `ot/index.html`，确保 GitHub Pages 直接访问、刷新和分享链接时不会 404。
- 首页桌面导航和移动菜单新增 `.ot 生态 / .ot Ecosystem` 入口；`.ot` 页面提供返回 OpenThesis 主站的明确入口。
- 中英文规则与主站一致：简体或繁体中文环境显示中文，其余语言显示英文，并保留手动切换。

### 5.2 内容原则

- 页面只宣传项目源码或正式文档中已经存在的 `.ot` 能力、对象和术语。
- 实施前从最新同步源码中建立 `.ot` 能力清单，并让页面文案逐项对应 2.0 已上线结果。
- 不展示伪造产品截图，不暗示文档范围之外的 UI、服务或兼容性。
- 页面将 2.0 能力作为已经交付的产品结果呈现，不使用计划状态标签或未来式表达。

### 5.3 页面信息架构

1. **生态 Hero**：以 `.ot` 核心对象为视觉中心，解释它在 OpenThesis 研究生态中的定位；使用代码原生的文件轮廓、字段标记与空间连线，不使用截图。
2. **对象解剖**：根据真实 schema、类型或文档，将 `.ot` 的组成拆成可验证的层级；滚动时逐层展开，而不是模拟应用窗口。
3. **生态连接图**：展示 `.ot` 与项目中已实现组件的真实连接关系；连接线只承担数据流或生命周期含义。
4. **生命周期**：使用真实命令、状态或处理阶段建立连续流程；用户滚动控制 `.ot` 对象在阶段之间演进。
5. **开放与安全边界**：呈现开放格式、签名、撤销、隔离验证和秘密扫描边界，并链接到真实源码或文档。
6. **CTA**：引导查看源码、阅读 `.ot` 文档或返回下载主产品；不提供尚不存在的下载入口。

### 5.4 无截图视觉系统

- 使用 DOM、CSS 与 SVG 构建 `.ot` 文件对象、结构层、真实字段标签、连接路径和状态标记。
- 核心对象采用克制的半透明深色材质与珊瑚色活动状态；不制作假浏览器、假桌面窗口或虚构公司数据。
- 桌面端与移动端均使用普通文档流中的局部 scroll-linked 动画；桌面扩大空间层级，移动端缩短位移与并发。
- 动效语法沿用主站：遮罩揭示、路径绘制、层级淡入、短距离视差和明确的 transform-origin。
