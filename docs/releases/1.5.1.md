# OpenThesis 1.5.1 系統語言自動偵測與繁體中文全面支援需求／驗收清單

狀態：**實作與 Windows 測試包已完成，等待使用者驗收；高 DPI 人工視覺檢查與受環境權限阻擋的 Rust 單元測試仍待閉環**
建立日期：2026-08-17
規則：本文檔完整取代 `1.5.0.md`，是 1.5.1 的需求凍結與驗收依據。第一輪只允許定位、設計與更新本文檔；使用者明確確認後才實作。完成後必須逐項驗收、打包供使用者測試；只有使用者測試通過並再次授權，才提交、推送與發佈 GitHub Release。

## 1. 目標與語言標準

### 1.1 支援範圍

- 新增完整的繁體中文專案頁面、應用程式界面語言與研究報告輸出語言。
- 新安裝預設跟隨作業系統語言：英語系統直接顯示英文，簡體中文系統顯示簡體，繁體中文系統顯示繁體；未來新增語言時沿用同一註冊表解析，不再改寫啟動流程。
- 界面語言與報告語言保持互相獨立：使用者可使用英文界面輸出繁體中文報告，或使用繁體中文界面輸出英文／簡體中文報告。
- 不使用雲端翻譯服務，不增加模型請求，不產生額外 API 費用；所有程式固定文字均由專案內建、可審查的翻譯目錄提供。
- 模型自然語言輸出透過不可覆蓋的報告語言約束要求繁體中文；JSON 欄位、enum、證據 ID、URL、數字及內部協定鍵保持英文穩定值。

### 1.2 標準語言值

- 內部 canonical 值採用 BCP 47 script tag：`zh-Hant`。
- `zh-TW`、`zh-HK`、`zh_Hant`、`zh-Hant-TW`、`zh-Hant-HK` 等舊值或外部值統一正規化為 `zh-Hant`。
- `zh-Hans`、`zh-Hans-CN` 等簡體 aliases 統一正規化為既有 `zh-CN`；`en-*` 仍歸一為 `en`。
- 既有 `zh-CN` 與 `en` 不變；未知值仍安全回退 `zh-CN`，不破壞舊設定。
- 界面顯示名稱為：`简体中文`／`簡體中文`、`繁體中文`、`English`，並依當前界面語言本地化。
- 第一版使用跨台灣、香港均可理解的中性繁體用語；公司法定名稱、官方財報原文及直接引文不做字形改寫。未來若需要台灣與香港術語分流，可在 `zh-Hant` 之上增加區域 profile，而不改資料庫 canonical 值。

## 2. 已確認的現況與根因

### 2.1 前端界面目前只有兩種語言

- `desktop/src/types.ts` 的 `Language` 僅允許 `"zh-CN" | "en"`。
- `desktop/src/i18n.ts`、`HelpView.tsx` 與研究進度文案僅有簡體中文和英文目錄。
- `SettingsView.tsx` 的界面語言與報告語言下拉選單都只有兩個選項。
- `App.tsx` 啟動時僅識別 `en`，其他值一律設為 `zh-CN`，因此即使後端保存繁體值也會顯示簡體界面。

### 2.2 Python 本地化目前是二元分支

- `src/openthesis/i18n.py` 的 `SUPPORTED_LANGUAGES` 僅包含 `zh-CN`、`en`；`normalize_language()` 對所有非英語值回退簡體中文。
- 固定界面文字以簡體原文作為 source，再使用 `UI_EN` 翻譯英文，尚無繁體目錄。
- 模型提供方、SEC 身份、研究狀態和錯誤訊息只有簡體／英文標籤。
- `comparison.py`、`financials.py`、`growth.py`、`report_projection.py`、`reporting.py`、`report_html.py`、`research.py` 與 `service.py` 仍大量使用 `English else Chinese` 判斷；新增 enum 而不重構會錯誤落入簡體文字。

### 2.3 報告輸出鏈路尚未認識繁體中文

- `ResearchRun.report_language` 雖為文字欄位、無需資料庫破壞性遷移，但目前進入 workflow 前會被正規化為 `zh-CN` 或 `en`。
- `OUTPUT_LANGUAGE_INSTRUCTIONS` 只有簡體與英文；所有 Agent、雙模型、修復與重試路徑都無繁體約束。
- Markdown、HTML、確定性財務摘要、增長機會、比較報告、錯誤說明、免責聲明及匯出內容都使用二元語言分支。
- 舊報告重繪必須只翻譯程式生成標題與確定性段落；既有 AI 正文保留生成時原文，避免不可重現和額外費用。

### 2.4 專案層面沒有繁體中文入口

- GitHub 專案首頁只有 `README.md` 與 `README.zh-CN.md`。
- 應用內離線幫助文章、關於頁和研究模組說明沒有繁體版本。
- 內建研究模組 manifest 僅聲明 `zh-CN`、`en`。

### 2.5 目前沒有系統語言偵測與可擴充註冊表

- `desktop/index.html` 固定 `lang="zh-CN"`，`App.tsx` 初始狀態也固定簡體中文；React 掛載後才讀後端偏好，存在首屏語言閃爍風險。
- 現有後端 `PREFERENCE_DEFAULTS` 永遠提供 `ui_language=zh-CN`，無法區分「使用者從未選擇」與「使用者明確選擇簡體中文」。
- 沒有 `navigator.languages`／Windows locale Adapter，也沒有「跟隨系統」和「手動選擇」兩種模式。
- 設定頁語言選項、`App.tsx` 判斷、HTML `lang` 與各目錄均硬編碼語言；新增第四種語言會要求修改多個無關頁面，擴充性不足。

## 3. 架構方案：語言註冊表與單一語言 seam

### 3.1 深模組界面

建立一個小而穩定的本地化 Interface，將語言複雜度收斂在單一 seam：

- `normalize_language(value) -> Language`
- `language_name(language, display_language=None) -> str`
- `localized_text(language, *, zh_cn, zh_hant, en) -> str`
- `translate_ui(message_id/source, language, **params) -> str`
- `output_language_instruction(language) -> str`
- `translate_error(error_code/message, language) -> str`
- `resolve_system_language(preferred_locales) -> Language`
- `resolve_ui_language(mode, stored_language, preferred_locales) -> Language`

前端維持同一個 `Language` union 與 `COPY[language]` Interface；所有頁面只取本地化後文字，不自行判斷繁簡。後端 transport、資料庫與研究產物只保存 canonical ID，不保存顯示名稱。

語言註冊表的每個 `LanguageDefinition` 至少包含：canonical `id`、aliases、系統 locale matchers、本地化顯示名稱、`htmlLang`、文字方向 `dir` 與語言包 loader。設定選項、HTML 屬性和系統語言解析全部由註冊表生成；頁面、設定表單和報告 renderer 不得維護自己的語言 switch。

前端與 Python 各有一個符合相同契約的 Adapter；以共享測試 fixture 驗證 ID、aliases、fallback 和顯示名稱一致。語言包按功能域拆分為 interface、help、progress、report、errors 等目錄，但只透過上述 Interface 暴露。新增語言時只新增註冊表項目、語言包和驗收 fixture，不修改 `App`、`SettingsView`、研究流程或報告 renderer。

### 3.2 相容與遷移

- 現有 `zh-CN`、`en` 設定、歷史研究和資料庫原樣可讀。
- 保存設定時將 aliases 正規化成 `zh-Hant`；API Key 仍不得持久化。
- 無法識別的舊值安全回退簡體中文並保留可診斷訊息，不使啟動失敗。
- 模型提供方、SEC 身份、market 等下拉框繼續使用穩定 ID，繁體只影響顯示標籤。
- 市場顯示資料補充繁體標籤但保持既有欄位相容，避免不必要的 sidecar contract 破壞。
- 雲端財報視覺識別的 `auto | ch | en` 是外部 OCR Adapter 協定，不與 `Language`／`report_language` 合併；繁體報告仍可使用 `ch` 識別中文財報。

### 3.3 系統語言解析與優先級

- 新安裝或 `ui_language_mode=system` 時，前端 SystemLocale Adapter 讀取 `navigator.languages`（依偏好順序）與 `navigator.language`；測試可注入 locale 列表，不直接依賴全域狀態。
- Windows Tauri WebView 無法提供 locale 時，使用本機 system-locale Adapter 的原始 BCP 47 tags，再交由同一純函式 resolver；legacy Tk 入口也只提供 raw tags，不重複語言映射規則。
- 解析順序：第一個已註冊的系統 locale → 註冊表 fallback。推薦未支援語言回退 `en`，而不是猜測為中文。
- `zh-Hant`／`zh-TW`／`zh-HK`／`zh-MO` → `zh-Hant`；`zh-Hans`／`zh-CN`／`zh-SG`／無 script 的 `zh` → `zh-CN`；`en-*` → `en`。
- `ui_language_mode=manual` 時，使用者保存的 canonical 語言永遠優先於系統語言；系統語言變更只在下次啟動套用，不在研究進行中突然切換界面。
- 舊版已真實保存 `ui_language` 的使用者視為 manual，避免升級後被系統語言意外覆蓋；資料庫沒有該 key 的新安裝才預設 system。
- 報告語言維持獨立。新安裝沒有 `report_language` 時，初始值採已解析的界面語言；使用者保存報告語言後，不再隨系統或界面自動改動。
- React 掛載前完成首次語言解析並同步設定 `<html lang>`／`dir`，避免先顯示簡體再切換；後端 bootstrap 只會以明確 manual 偏好覆蓋。

## 4. 專案與界面繁體中文

### 4.1 專案獨立入口

- 新增完整人工校對的 `README.zh-Hant.md`，不是執行時自動簡繁轉換。
- 三份 README 頂部互相提供 `English · 简体中文 · 繁體中文` 導航。
- 繁體 README 覆蓋產品定位、功能、安裝、語言設定、模型入口、隱私與安全、研究模組和開發流程；不得只做摘要頁。
- 後續 1.5.1 Release Notes 同時提供簡體中文、繁體中文與英文，但發佈仍遵守使用者測試後再授權的流程。

### 4.2 應用界面

- 設定頁的界面語言與研究報告語言均加入 `繁體中文`。
- 界面語言提供「跟隨系統（目前：…）」與三個手動選項；語言清單由註冊表生成。報告語言保持三個明確輸出選項，不把模糊的 `system` 值寫入 `ResearchRun`。
- 繁體界面仍沿用現有規則：保存後提示重新啟動，重啟後生效；不重建當前視窗、不清除研究狀態或會話 Key。
- `COPY` 完整覆蓋導航、研究、歷史、投資邏輯、設定、幫助、關於、進度、視覺兜底、錯誤、彈窗、空狀態、匯出與無障礙標籤。
- 離線幫助三篇文章全部提供繁體版本；程式碼範例和協定鍵保持原樣。
- 研究進度階段與等待提示提供人工校對的繁體文案，切換節奏和 reduced-motion 行為不變。
- legacy Tk 界面若仍保留為可執行入口，也必須透過同一 Python 本地化 seam 顯示繁體，不允許只支援 Tauri 發佈版。

## 5. 模型與研究報告繁體中文

### 5.1 Agent 輸出約束

- `zh-Hant` 指令要求所有自然語言值使用繁體中文，保持 JSON keys、enum、ID、URL、數字、公司正式名稱與證據引用不變。
- 約束注入每一個 Agent、第二模型、最終綜合、增長階段重試、綜合修復及自訂 `.othesis` 模組，且不可被模組 Prompt 覆蓋。
- 不新增翻譯 Agent、不自動再次呼叫模型；第三方模型未遵守時記錄安全診斷，不能靜默改成簡體中文或偽稱已翻譯。

### 5.2 確定性與渲染內容

- Markdown、HTML 與匯出報告的章節、欄位、財務表頭、置信度、證據等級、情景、主要結論、反方觀點、失效條件、未解問題和免責聲明均有繁體目錄。
- 繁體 HTML 報告根節點必須標記 `lang="zh-Hant"`，簡體與英文分別維持正確語言標記。
- 確定性財務概覽、季度／中期同比、反向 DCF、驗證結果、雙模型比較和錯誤／缺口原因均使用繁體文字。
- 非技術模式不得因新增語言重新洩漏英文協定鍵、evidence IDs 或內部診斷。
- 歷史報告依使用者當前選擇重新渲染程式標題與確定性內容；原有 AI 正文保持原語言，並清楚維持該次 `report_language` 記錄。
