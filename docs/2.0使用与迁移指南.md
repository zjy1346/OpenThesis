# OpenThesis 2.0 使用与迁移指南

> 本文以中文说明 2.0 的实际使用边界。英文术语后附中文含义。  
> 2.0 正式发布前，本文随本地测试包一起验收；未经用户测试通过和明确授权，不发布 GitHub Release。

## 1. 从 1.5.1 升级

2.0 使用原有本机用户数据目录继续读取非秘密偏好和历史研究。界面语言、报告语言、侧栏状态、并行 Agent 选项和研究市场仍按原设置键读取。

旧模型配置不会被当作安全凭据迁移。原因是 2.0 改为 Windows Credential Manager（Windows 凭据管理器）和不含秘密的模型引用，无法证明旧会话字段仍然有效或安全。升级后请在“模型中心”重新建立连接、保存凭据、添加模型并执行测试。

不要把旧设置文件中的 Key 复制进 Issue、日志或 `.ot`。确认 2.0 连接可用后，再按自己的安全策略清理旧版本遗留的临时资料。

## 2. 不再支持用户 `.othesis`

2.0 不打开、导入、安装、运行或通用转换用户和第三方 `.othesis` 文件。文件选择器只接受 `.ot`。

项目自己维护的旧官方包已经通过固定源目录的开发期工具转换为官方 `.ot`。这个工具不是用户兼容层，不扫描用户目录，也不会被正式应用调用。

如果你维护第三方旧包，需要在 OT Studio 中按新结构重新编写并验证，而不是修改扩展名。

## 3. 首次配置模型

1. 打开主导航中的“模型中心”。
2. 选择 Provider（模型服务商）卡片。
3. 查看官方注册/密钥入口和数据发送边界。
4. 新建一个连接；同一 Provider 可以创建多个连接。
5. 需要 API Key 时输入一次并保存。页面之后只显示“已配置”，不会回显旧密钥。
6. 点击“发现模型”，或手动输入模型 ID。
7. 选择一个或多个模型并添加。
8. 对每个模型执行“测试”。只有启用且状态为可用的模型会出现在研究页和 OT Studio。

自定义远程 OpenAI-compatible Endpoint 会显示完整 Origin（协议、主机和端口）并要求确认。不要把 Key 发送到不信任的地址。

## 4. Windows 凭据与恢复

API Key 保存在当前 Windows 用户的 Generic Credential（通用凭据）中。SQLite 保存连接 ID、Provider、Endpoint、凭据引用、版本和健康状态，不保存明文 Key。

出现以下情况时可能需要重新配置：

- Windows 凭据条目被手动删除；
- 更换电脑或 Windows 用户；
- 系统重装；
- 管理员重置密码导致凭据不可恢复；
- 凭据库损坏或被安全策略阻止。

应用只提示“需要重新配置”，不会尝试从日志、数据库或历史报告恢复秘密。

替换 Key 使用“暂存 → 测试 → 原子切换 → 清理旧版本”流程。删除连接会清理系统凭据和该连接的模型元数据；删除单个模型不会删除连接或 Key。

## 5. Ollama

OpenThesis 不内置、不安装也不下载 Ollama 或任何模型。

使用方法：

1. 用户自行安装并启动 Ollama；
2. 在模型中心选择 Ollama；
3. 默认连接 `http://localhost:11434/v1`；
4. 发现当前 Ollama 已经安装的模型；
5. 添加并测试需要的模型。

本机 Loopback（回环地址）会标记为 Local（本地）。如果把 Ollama Endpoint 改成远程地址，界面会明确说明研究内容将离开本机，不会把远程服务标记为本地。

## 6. 免费模型

2.0 可识别的零云端调用费或 Free Tier（免费额度）路径包括：

- 用户已有的本机 Ollama；
- Provider 官方元数据能够核对的免费模型或免费路由，例如 OpenRouter Free；
- Gemini 等 Provider 当前提供的免费额度入口（具体额度以 Provider 当前规则为准）。

`Free` 不是“永久免费”保证。模型列表、额度、地区、排队和速率限制都可能变化。429、额度耗尽或模型下线会返回明确错误，不会自动切换到收费模型。

GitHub Models 已从当前 Provider 目录移除，不作为 2.0 免费入口。

## 7. 发起研究

1. 先在模型中心完成模型配置和测试。
2. 打开“新建研究”，选择市场与公司。
3. 选择一个主模型；比较模型为可选且可以多选。
4. 需要财报页面模型兜底时，选择一个已经测试且声明 Vision（视觉）能力的模型。
5. 确认 SEC 身份、报告语言、市场数据和上传边界。
6. 开始研究。

研究页不出现 Provider、Endpoint 或 API Key 字段。运行记录只保存已配置模型 ID、配置版本、角色和参数，不保存秘密。

## 8. OT Studio

OT Studio 有引导模式和专业模式：

- 引导模式提供目标、包 ID、版本、研究周期、深度、风险权重、工作流、输出和证据开关；
- 专业模式允许编辑完整草稿 JSON；
- 撤销/重做保留本次编辑历史；
- “检查草稿”只执行验证；
- “检查并导出 .ot”编译确定性容器并调用系统保存框。

字段助手是可选能力。只显示模型中心中已经配置、启用且测试通过的模型；免费模型显示 `Free`。一次只建议一个允许字段，用户可以接受或拒绝。没有模型时仍可完成所有手动工作。

格式规范见 [OT_FORMAT_2.0.md](OT_FORMAT_2.0.md)。

## 9. 当前限制

- 正式二进制目标仅为 Windows x64；macOS/Linux 暂无正式包。
- 金融机构研究仍为 Beta。
- 不自动抓取实时价格或市值。
- 不连接券商，不执行交易，不提供短线信号。
- 数据源可能受官方站点可用性、速率限制和报告格式变化影响。
- 视觉兜底必须由用户启用、选择模型并同意数据发送。
- 第三方 Provider 的价格、免费额度、服务状态和模型目录不由 OpenThesis 控制。

## 10. 隐私检查

发布包、普通设置备份、报告和 `.ot` 不包含：

- API Key、Token 或密码；
- SEC 联系邮箱；
- 研究历史数据库；
- 用户本机绝对路径；
- Ollama 或模型权重；
- 用户或第三方旧 `.othesis` 资产。

如果错误信息疑似包含秘密，请停止分享，先撤销对应 Key，再提供已经脱敏的错误类型、Provider、阶段和时间。

## 11. 2.0 验收顺序

正式发布前必须：

1. 完成 Python、TypeScript、前端、Rust 和打包测试；
2. 扫描发布包中的秘密、个人路径、Ollama、模型权重和旧 `.othesis`；
3. 逐页检查导航、按钮、输入、滑块、下拉栏、弹框、错误、忙碌、取消和恢复状态；
4. 在 OT Studio 真实生成、保存并重新读取一个 `.ot`，记录内容身份；
5. 使用受控无秘密模型或用户配置模型真实完成一次研究，覆盖确定性分析、Agent、综合、验证和可复现性记录，保存 `run_id`；
6. 先交付本地 2.0.0 测试包；
7. 只有用户测试通过并明确授权后，才允许提交、推送和发布 GitHub Release。
